# 数据模型与存储读取规则

## 存储与读取规则（一页版，2026-11-07定稿）

以下是用户确认的目标规则，数据库选择已确认为单个SQLite；已完成导入核对、恢复和只读日常切换，旧数据保留、旧运行读取已退役；2026-11-10本人已验收通过并确认加载时间符合预期。本人已于11-08批准按方案实施，方案独审已通过，实施与最终验证门槛见[任务书](tasks/TASK-20261107-storage-read-baseline.md)。先覆盖关注池，结构按全市场可扩展设计；基准规模为6000股票＋1500ETF、各2500日，不代表已准入这些来源或拥有这些历史。

1. **行情按行入库。** 事实主键为标的身份＋交易日期＋行版本；JSON可存元数据，不再承载行情数值快照。发布版本引用行版本，不能以每次发布复制多年事实来实现版本。
2. **十进制原精度。** 价格、成交额保留官方精度、单位及不复权原值。SQLite用十进制TEXT，后端用Decimal；禁止转REAL或浮点运算。缺失、撤回、不支持与真实零分开，原精度不得被展示舍入覆盖。
3. **原件按内容去重。** 原始响应、PDF以内容指纹寻址，同字节只存一份；数据库保存来源、获取时间、指纹与引用。相同内容的多次获取保留各自观察记录。
4. **修订只追加变化行。** 新发布仅追加变化事实及必要引用/元数据，旧行不可覆盖。每行可直接或经固定外键追溯来源、发布时间、获取时间、版本；未知发布时间明确为空，不用获取时间补造。回溯取得不等于历史当时可知。
5. **复权另存。** 分红送转等事件及因子独立带来源和版本；前后复权按指定事件/因子版本由后端按需计算，不作为来源事实或覆盖不复权价格。
6. **ETF日指标独立。** 份额、净值等按标的＋日期＋指标＋版本保存，各自绑定来源、单位、时间与缺失状态；一项更正不连带改写其他指标。分析仍须显式选定固定输入组合。
7. **页面只读库。** 在一致只读事务内固定发布版本，按标的和日期范围取有效行；不读原件、不重放旧JSON快照。旧报告固定版本仍可解析；仅“查看证据”读取获准的原件并核验指纹/归属。
8. **校验前移。** 来源、身份、精度、完整性、时间和发布一致性在写入/发布边界完成，失败不得发布；普通读取不再逐文件重验。另设定期完整性检查并记录结果，损坏明确报错/隔离，不能静默修复；接口权限和参数检查仍保留。
9. **按需返回、按版本缓存。** 图表只取所需范围及计算必需的前置窗口，不附带多年全量历史和原件。响应带固定版本；轻量检查是否更新，缓存键含数据范围、输入版本、公式、参数和复权口径，防止串用。
10. **派生结果现算。** 涨跌幅、均线、周月K由后端基于固定输入现算，用有上限的进程内缓存；已引用的历史信号/计算依据继续保留，不用现算结果冒充过去的结论。
11. **单写者与保留。** 仅后端更新任务批量写入并原子发布；操作账本、旧版本分活动与历史管理，超期压缩/归档，保留指纹目录和可恢复引用。未结束操作、未核销额度、被报告引用的原件/输入及笔记不自动清理；本轮保持原数据与旧版本，恢复步骤见架构；清理周期尚未批准，不自动压缩、归档或删除。

迁移方式已决定：一次性脚本导入，按对象核对条数、内容指纹及引用关系，验证备份恢复后删除旧读取路径；不做兼容层、不长期保留双存储。删除旧读取代码不等于删除旧数据，本轮旧数据全部保留。已授权实施须先方案独审，备份、核对、恢复与代码独审通过后切换；采集和定时更新保持关闭。阶段性能门槛归[PRD §3](PRD-V0.1.md#3-可观察结果与边界)，数据库测试不能替代首页端到端验收。

## 与迁移前设计逐条核对

| 条 | 迁移前设计与冲突 | 本轮实施选择 |
|---|---|---|
| 1 | 冲突：价格SQLite只登记快照/观察/指针等，数值在对象JSON；量额数值也在JSON。 | 增加行级事实表；旧快照ID转为可解析的版本/行引用，不复制数值。 |
| 2 | 十进制原精度与现规则一致；股票不复权事实尚非当前指数交付内容。 | 保留现有精度，扩展时登记价格类型/单位；不能从本规则推导已批准股票来源。 |
| 3 | 方向一致但实现分散：指数、量额、ETF各有对象根，跨根未统一去重。 | 导入时按字节指纹去重，原ID/来源/观察时点映射保留；原件与事实库分开备份。 |
| 4 | 冲突：价格/量额按窗口保存整份快照；ETF输入对象可去重，但每次仍生成完整输入引用清单及重算档案。 | 追加变化行＋紧凑发布记录；观察记录独立追加，未变化数值不随发布复制；保留旧版输入身份。 |
| 5 | 当前指数价格无个股复权模型；ETF已有调整证据，不能当作完整股票事件模型。 | 迁移既有调整证据；股票事件/因子作为独立结构，来源和可知时间仍需准入验证。 |
| 6 | 冲突：ETF以Input对象聚合份额/净值等字段，未按独立指标表存储。 | 拆为带各自来源/版本的指标行，原输入组合及信号引用可追溯。 |
| 7 | 直接冲突：价格`_read_snapshot/_read_receipt`、量额`Store.fixed`及运行层、ETF`Repository.load`读取并验证原件/对象。 | 页面查询改为固定版本SQL；证据端点单独读原件；保留只读不建库、不恢复、不联网的边界。 |
| 8 | 直接冲突：迁移前[架构](Architecture-V0.1.md)要求每次重读证据并核验来源重放，不缓存证据有效性。 | 迁移时将保证改为发布时验证＋定期完整性检查；存在检查间隔内损坏未被提前发现的窗口，读取错误仍须报告。 |
| 9 | 部分冲突：现有概况/详情与紧凑响应仍返回完整快照，无所需日期范围的行查询。 | 后续调整服务/前端和唯一HTTP契约；缓存按版本及全部语义参数区分，参数边界不由浏览器决定。 |
| 10 | 总览现算和进程缓存已部分一致；ETF原信号/重算档案属于研究依据。 | 沿用确定性公式与缓存上限；不借此删除ETF原信号、固定输入或已保存历史结论。 |
| 11 | 已有后端排他写、账本与恢复边界；统一压缩/归档策略未落地。 | 给活动/历史对象设保留目录、可恢复归档和容量预警，不能靠清空额度账本或删除引用对象腾空间。 |

实际产品仍是已准入的固定三年指数窗口和既有ETF能力；十年与全市场是压力模型，不扩大日历、来源或功能。工作区已采用统一SQL读取及3.0.0范围契约，候选库导入、逐版本核对和恢复副本检查已完成；性能、适用独审、只读日常切换及旧读取退役已完成，2026-11-10本人已验收通过并确认加载时间符合预期，具体边界及原失败记录见任务书。[架构迁移方案](Architecture-V0.1.md#单sqlite迁移实施方案2026-11-08方案独审通过实施中)固定恢复身份、范围读取和完整性检查，HTTP结构只编辑[OpenAPI](../contracts/openapi.yaml)。金融与保留红线见[业务约束](Business-Constraints.md)，数量盘点及进度见[本次任务](tasks/TASK-20261107-storage-read-baseline.md)。
