# 本地数据保存范围：市场参考与研究档案

修订：2026-10-04。需求及首批名单以 [PRD §5](PRD-V0.1.md#5-v01-范围契约) 为唯一来源；本文件负责保存边界、触发与恢复语义。来源能力见 [Data Sources](Data-Sources-V0.1.md)，当前授权见 [status](status.md)。本次文档调整不启动采集、回填、调度或迁移。

## 1. 保存原则与范围层级

以少量长期公共参考数据、重点证券与真实研究需要的数据支持市场看板和投资论点。取消原方案“必须先建全市场个股日线底表与全市场公告索引”的前提；市场统计仍需有来源、范围和可核验依据。

| 类别 | 内容与价值 | 保留方式 |
|---|---|---|
| 基础参考数据 Reference Dataset | PRD 已选的指数、市场统计、商品、汇率、利率与货币信用序列；便于稳定查询和一致计算 | 长期保存标准化事实与必要来源/版本，不按普通缓存到期删除 |
| 重点证券数据 | 自选、用户定义的行业龙头、持仓及实际研究所需证券的行情、适用估值和必要身份/公司行为 | 按明确关注或研究范围积累；取消自选保留历史 |
| 历史证据与用户档案 Historical Evidence | 当时公告/网页/预测/原始宏观发布、固定计算输入、原话、论点、规则、个人状态、决定和复核 | 版本追加，保护固定引用与重放依赖；不能以“网上还能下载”为由替换或删除 |
| 可重建缓存与暂存 | 图表序列、聚合缓存、搜索索引、无引用下载暂存和诊断日志 | 在依赖可恢复且无保护引用时可回收；成为决定/报告证据后保护必要版本 |

公共参考数据可重新取得不代表应该自动删除；历史证据可追溯不等于所有旧网页或首次发布版本都能够补齐。两类长期数据都服务研究，后者承担不可替代的决策历史记录。

## 2. 市场统计与必要上下文

- 保存所选指数身份、编制方、收益类型、交易日历、日线与适用估值，不默认先建设全部历史成分股数据库。需要重建指数、解释贡献时再验证历史成分和权重。
- A 股涨跌与成交统计可以直接使用可靠来源的同口径每日汇总，或以当日证券截面计算。两条路径都须与可取得的官方同口径数据核验，不能强迫为每日统计永久保存所有个股的五年全字段历史。
- 来源汇总保留原始发布、统计范围、日期、更新时间、单位、规则和缺口；不能声称可钻取其未提供的个股明细。本地计算保存当日样本范围、计算输入/版本、分母和算法依据，使已固定结果可复算。
- 停牌、无可比昨收、缺失与平盘分开；涨跌停按证券当日适用规则及收盘状态判断，不统一套用固定百分比。证券状态与名单历史按计算需要保存。
- A 股与港股分别明确证券范围、成交范围、币种与交易日历；汇总不直接跨币种相加。港股涨跌统计若超出已确认清单，应另行明确范围。
- 若以后建设行业视图，行业成员历史不足时仅显示可靠的当前/已采集快照，不能用今天名单回算过去。行业与概念仍分开。

市场汇总进入长期参考库；其计算依据若进入决定/报告，受引用保护。直接来源汇总的核验能力与逐股复算能力分别披露。

## 3. 重点公司与研究档案

| 内容 | 范围与触发 | 保留与说明 |
|---|---|---|
| 身份、日线、复权与估值 | 自选/持有/用户定义龙头/实际研究证券，具体名单由使用确定 | 保留来源、单位、有效期间和版本；没有合法因子不生成伪复权 |
| 公司公告与财报 | 围绕重点公司和真实研究问题归档；不要求全市场公告索引先行 | 原件、发布时间、报告期、更正关系与页码/表格定位；索引存在不等于原件离线可读 |
| 业务、订单与收入证据 | 正式披露、IR、可追溯外部资料；按研究问题组织 | 公司自述保留性质；概念或技术储备不证明已有收入 |
| 历史时点资料 | 当时使用的新闻、网页、预测、报告、公告和宏观初值 | 保留具体版本与何时可知；后续找到的资料不能自动补入旧决定 |
| 原话、结构化论点及修订 | 用户记录、AI辅助和用户确认各有身份与时刻 | 原话不被AI覆盖，原始版本、结构化版本和后续修订分别保存 |
| 决定、规则、状态与复核 | 与实际决策/不操作/复核事件关联 | 固定当时版本，后续更新不改旧决定；个人资金状态仅记录必要信息 |

同一证券可以有多个关注和研究原因。取消自选只取消该关注关系，不删除已有档案，也不自动取消其他仍有效的研究或监控。全部理由消失后是否停止增量，须在更新策略中明确；本轮不启用后台更新。

财务结构化、行业专属指标和全自动解析按需要扩展。AI分析记录属于分析产物，不能重新包装成独立外部证据；可复算计算须固定原输入和公式。

## 4. 历史深度与更新方式

历史目标、日线级别与默认保留原则统一见 PRD §5.3；时间语义见 [数据模型 §2](Data-Model-V0.1.md#2-时间模型不止-published_at)。五年能力按序列和字段验证，不能从行情覆盖推定估值、资料原件或历史版本同样齐全。

| 类型 | 后续更新设计依据 | 未完成/失败时 |
|---|---|---|
| 日线、指数、日度指标 | 对应市场交易结束且来源完整可用；时区、夜盘交易日与价格类型分别定义 | 保留上一可用版本，显示实际日期/缺口 |
| 月度货币与信用数据 | 官方发布后更新，分开记录统计月份、发布日期和修订时间 | 不插值伪造每日观测，不沿用统计月末作为首次可知时刻 |
| 政策利率、身份和规则 | 公布/生效事件与有效区间 | 无公告支持的历史区间标未知 |
| 公告、财报与资料 | 按关注/研究策略，在披露或检查时发现 | 抓取、下载、解析状态分开；不把发现标题当成归档成功 |
| 派生指标 | 输入版本、公式、口径或窗口变化 | 新结果另有版本，固定历史输入与结果不变 |

手动还是自动更新、应用关闭后的追补方式待设计。收盘后使用不等于授权定时采集；既有切片的真实运行行为以 README 与已归档任务为准。

## 5. 每类数据共同需要保存的上下文

至少能回答：是哪种标的/序列、属于哪天/哪期、何时生效/公开/获取、来源是谁、单位与币种是什么、采用什么价格/统计口径、历史版本支持到哪里、缺口是什么。

跨市场商品保留现货/期货/基准价类型；连续期货保留合约选择、换月、调整规则及原合约依据。上金所与上期所不混淆，USD/CNY与USD/CNH不混接。具体序列未定前不创建含糊的“黄金价格”“铜价”事实字段。

金额、数量、比例与报价单位按资产定义；来源原始单位和转换版本一起保存。数据快照固定金融输入，决策快照还固定用户表达、论点、规则、状态、分析和决定，不能用行情批次替代。

## 6. 空间、清理与暂不纳入的数据

150 GB 是软上限，具体容量与峰值按已选数据实测。达到预算压力时先提示、暂停非必要下载并讨论范围或存储调整；不按固定年限滚动删除长期历史，也不删除取消自选证券的已有历史。

可回收无保护引用的可重建缓存、索引、过期诊断日志与确认无依赖的失败暂存。内容去重保留来源关系；固定计算依赖、决策原话、规则旧版本、历史证据及用户笔记不作为普通缓存清理。

暂不建设全部个股长期完整数据库、全市场公告附件/新闻/研报全集、全行业宏观平台、分钟/Tick/逐笔/Level-2、完整海外证券库。公共序列扩充与更深公司资料由实际需求支持。

## 7. 可验证条件与实施顺序

- 所选参考数据、重点证券与来源汇总各自可说明范围、历史覆盖和质量，不冒称全市场明细完整。
- 本地计算可回到必要输入；来源汇总可回到发布证据，二者能力不混淆。
- 固定资料和计算在来源修订后保持原依据；取消自选后历史仍可读。
- 断网可读已完成归档的内容，更新失败与中断不破坏上一有效版本。
- 论点、决定和复核后续接入时继承版本与引用保护，不先建完全部未来 schema。

实施顺序统一见 [路线图](Implementation-Plan-V0.1.md)，本文件不维护另一份任务清单；具体授权统一见 status。
