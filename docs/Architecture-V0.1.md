# 当前架构

浏览器（React/TypeScript/ECharts）通过受控本机HTTP连接 Python/FastAPI 服务。`browserHost`读取可信启动描述；基础`ApiClient`核对协议、配置和实例，指数/量额/ETF Client负责各自契约。页面不能直接读取SQLite或业务文件，浏览器不负责采集调度。

服务装配为HTTP边界 → 更新协调／公开MarketData门面 → 指数、量额及预算实现。保留父写锁、只读事务、快照成员校验、来源校验、原子发布与操作身份。`update_service`服务当前参数化指数和量额启动/周期流程，不承载退役操作。

## 原子发布与恢复

当前工作区实现统一SQLite事实库与按SHA256命名的原件池，价格、量额、ETF在库内保留独立逻辑域。只读入口不建库、不恢复、不采集；事实、来源、版本及发布依据不可变，current和操作状态由单写者事务提交。旧格式仅用于一次性导入及隔离恢复核对，不能作为运行回退。已切换匹配的只读日常固定发布，2026-11-10本人已验收通过并确认加载时间符合预期，实际结果见任务书。

普通页面固定发布和观察ID，从SQL取得概况或所选日期范围及必要前置窗口，后端现算派生结果。原件校验在导入、写入发布、定期完整性检查及显式证据读取执行；正常页面不打开原件。服务计算缓存上限12项/32MiB，浏览器32项成功结果和32项进行中请求；固定目标请求复用，调用者取消不影响其他等待者，重连关闭旧连接。金融身份、参数、日期、缺失及完整性检查继续保留。

## 协议与运行边界

OpenAPI 3.0.0是当前匹配发布的唯一HTTP结构来源；安装包资源和浏览器校验器由同一源生成。保留现役health、session、index-series、market-activity、overview及etf-flow能力，新增轻量版本查询；不恢复退役API。契约指纹、配置及实例身份拒绝旧连接，旧固定读取接口也由SQL实现。

浏览器宿主按原资源地址直接发送已生成的独立ESM校验脚本，字节与生成产物相同，避免重复转换及附带调试映射。沿用同一Host、Origin、转发头及响应头限制；该静态资源仅允许GET/HEAD，不改变API或校验接受集合。

ETF通过MarketData门面使用同一库中的独立逻辑域、冻结观察池/证据/授权配置和不可变版本；缺省禁用，读取不建库、不采集、不恢复。显式更新绑定原计划与前提快照；ETF自身请求额度独立，启用总览周期协调时共用零计费排他租约，仅显式恢复自己的零计费租约。ETF不加入总览自动调度目标。页面与操作中心共用当前主连接，托管宿主生成可选ETF公开描述。

托管启动器生成一次运行的描述文件，管理自己的服务和Vite进程。服务退出、父管道断开或身份变化都必须停止相应连接；不会接管已运行的其他实例。周期调度仅在服务存活期间运行，不建立系统任务。

旧实现及未验收增量本地保全，干净master采用无旧父提交的新基线。本轮全部迁移门槛及独审通过后可切换匹配的日常固定发布；金融采集、定时更新及数据删除不在切换动作内。

### 身份、旧备份恢复与回退

物理路径与逻辑身份分开：新库登记不可变库身份及价格、量额、ETF的逻辑域；导入表显式绑定旧scope、原规范根、旧配置摘要及新库域。迁移保留旧ID、scope、额度累计、请求/计划/操作身份；新HTTP运行配置身份重新生成，用于拒绝旧客户端，不重算历史操作身份，也不初始化新额度。未来整库恢复到新目录沿用库内逻辑身份，物理路径只接受可信启动配置并冻结文件身份；旧配置不得成为可读路径。

旧备份异地恢复分两项验证，不能声称未修改的旧程序天然支持换目录：

1. 按冻结清单原样恢复三个根到独占目录，逐文件字节/指纹核验；配置原字节、旧根字符串、scope、固定ID及额度不修改。恢复目录与真实源、备份、新目标均不重叠；不跟随运行包依赖符号链接。
2. 用固定旧代码的离线读取验证器验证副本。验证器仅在进程内提供**物理路径→原逻辑路径的显式映射**：ETF Store的scope计算、周期scope计算、ETF配置身份中参与摘要的路径三处使用清单记录的原逻辑路径；所有实际文件定位、文件身份/权限/内容检查仍使用恢复副本。原scope比较、配置摘要比较、固定版本/原件/额度/操作验证均保留；不写副本初始化标记、不改账本、不覆盖scope字段、不忽略校验失败。映射只能由已核对的冻结清单产生，不能由待验证对象自报scope；每个映射先核对原清单摘要、恢复前后文件指纹及旧身份计算结果，缺项或不一致即失败。验证器属于一次性迁移/恢复工具，不能被服务或产品导入，交付服务没有此映射或旧存储回退。

验证进程装文件访问审计：原三个根及其真实路径别名全部拒绝；源金融文件、SQLite连接和配置读取必须落在恢复副本，依赖/固定代码只允许白名单只读位置；网络出站、写库、写文件、初始化及采集入口禁止。记录实际打开路径。先在假数据上证明无映射拒绝、正确映射成功、错误映射/篡改scope或额度/偷读原根拒绝，再用于真实副本。原路径回退单独指“切换前旧根未变，重新指向原根及匹配旧发布”，不把异地验证器当日常运行兼容层。标的查询和退役切片仅做离线固定对象读取，不恢复页面/API。

新库另做备份→另一目录恢复→数据库全字段/版本/原件/额度核对→新服务只读页面验证，且通过同样的原根拒绝审计。所有恢复验证停止更新、无网络采集；已保存历史身份仍能查询，HTTP运行身份随物理配置更新。若新库已有新业务写入则冻结保全，不直接回滚丢弃。

新值/原件/发布凭据在同一准备批次内验证，原件文件和目录先同步，再提交行版本、观察、绑定、成功凭据及current；异常保留上一发布。验证器函数与数据库读投影分离：普通查询只读已发布结构化行及成功凭据，不调用来源重放器、不打开原件。写入失败/中断、坏来源、错时点、错误范围、重复和CAS竞争需有隔离反例。旧发布时点不由迁移检查时间替换；新检查时间只是迁移验证证据。
