## 4. 建议实施契约

以下契约随第 1 节建议范围一并确认。常规内部结构可自主决定；关键语义变化返回用户。

1. **完整交易日**：使用有来源及覆盖区间的深交所开市日历，不能把原窗口的“周一至周五”算法直接推广。建议首版保守采用 Asia/Shanghai 当前日期之前最近一个已结束开市日，不纳入当日盘中或盘后数据；界面明确“完整日线不含当日”。这会在开市日盘后落后一天，须随范围确认。超出已核验日历覆盖时拒绝更新，不能猜测未来节假日。
2. **覆盖判断**：据独立日历确定目标截止日及向前 60 个开市日，再核验两来源的逐日覆盖与现有价格、股数、成交额口径。不能按接口返回的最后 60 行反推日历，也不能因源落后而缩短目标并声称最新。缺日、停牌状态不明、少于 60 日或两源冲突时保留旧快照并说明原因，不填零、不删除日期或静默换源。本轮不承诺通用停牌处理。
3. **变更与无变化**：区分业务窗口/数值有变化、仅原响应或来源证据变化、无变化、来源未就绪、失败。已有完整窗口仍应核验重叠日期，以发现窗口内修订；窗口外修订不保证发现。无变化也记录本次成功检查时间，但不伪造业务新增天数；如原件变化导致新快照 ID，应如实说明仅证据变化，不为追求同 ID 丢弃原件。
4. **时间与顺序**：分别保存每份新原件的获取完成时间、此次观察时间及检查结果。重放沿用原观察身份；新观察不得冒用旧时间。当前快照首次获取时间不是最近检查时间。更新入口另需防止较晚获取的陈旧窗口把行情截止日退回；不能破坏存储层“旧内容在真正较晚观察时可以重新成为当前”的既有契约。
5. **公告复用**：从已验证的本地对象复用两份公告及其证据定位，不随日线更新重新获取或宣称发现新公告。缺失/损坏则明确报错，不能降为单公告成功。保留其已知发布时间、原获取依据及未知项，不能以新行情获取时间替代公告原获取时间；重点检查现有 `public_available_at` 随快照 `first_seen_at` 派生的路径。必要的新元数据只影响新版本，旧固定视图保持原值，不补造旧逐原件时间。
6. **发布与恢复**：仍是原件持久化、校验通过后事务发布。错误或提交前中断不改当前指针；提交后客户端失联，应通过查询状态/当前版本确认结果，不能直接重发抓取。重启后未完成任务标为中断或结果待核对，允许人工重新发起；不要求跨重启自动续传。旧快照及 PDF 固定链接必须仍可用。
7. **单次任务与访问控制**：建议受保护的 POST 启动、GET 查询状态，返回任务标识、阶段、结果代码及相关快照 ID；具体路由命名由执行者决定。同一数据根只允许一个更新写入者，重复点击返回运行中任务或忙碌；CLI 与服务如均可写也须防冲突。读取继续可用。拒绝客户端自选 URL、数据根、证券或获取时间；未授权请求不能发出外网请求或写入。任务轮询仅查本地状态，不重复抓上游。
8. **请求预算**：建议单次每个行情来源至多 2 次请求（首次及一次有界重试）；429/403、格式变化或质量冲突不盲重试，不绕过限流。网络超时、总时限和响应大小必须有界并记录实值；沿用现有上限，确需调整须给真实样本依据。新任务被明确执行前不进行实际取样。
9. **界面**：复用现有布局，在行情标题附近放“更新日线”。默认显示截止日及最近检查时间（旧记录未知就显示未知）；运行中禁重复触发并显示阶段；成功/无变化/失败各有明确提示。失败保留旧行情与公告，空库提示先准备切片；无后台定时刷新。切换快照时处理正在读取的 PDF 响应，避免旧响应覆盖新选择；键盘可操作，窄窗口可读。开始局部 UI 实现前落实这一状态布局。
