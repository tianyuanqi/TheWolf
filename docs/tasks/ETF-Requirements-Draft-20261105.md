# 大资金动向（ETF份额监测）需求说明 · 修订稿

需求修订日期：2026-11-05；迁入说明：2026-11-07。状态：本轮迁入开发，用户验收待完成。

本稿保留既有ETF业务定义，作为[PRD](../PRD-V0.1.md)的大资金动向需求附件。历史原型与开发材料留在项目外保全；本轮已获准将需求和代码迁入`codex/etf-flow`，接入范围见[迁入任务书](TASK-20261107-etf-flow-integration.md)。按较晚确认的页面设计，默认展示60日。真实配置、取数、启用、提交、合并和推送不由本文授权。

第一期仅启用用户指定的一只ETF，身份信息集中在附录A的初始配置草案。设计、数据层、规则和测试均按可更换的观察池设计；支持换配置，不表示获准加入更多真实ETF。

## 0. 目的与业务边界

通过ETF份额变化估算净申赎对应的价值，观察异常变化，并结合具名持有人披露、官方公告、成交和折溢价，为用户研究汇金等主体的活动提供线索。

- 金额属于ETF或观察池，不能称为国家队实际买入、卖出或持仓金额，也不是实际现金净流入。二级市场交易本身不改变基金总份额；实物申赎、套利等也会影响份额。
- 主信号使用“异常净申购／异常净赎回”等可解释名称，不输出国家队入场概率、强弱评分、预测或买卖建议。
- 正式业务指标、有效成员判断和信号由可信后端计算；前端负责交互、绘图和格式化。AI通过受控工具读取资料及计算结果，不用模型记忆补金融事实。
- 红色表示份额增加／净申购，绿色表示减少／净赎回，零值为中性；缺失与零值分开。
- 第一期不增加融资融券、北向资金、个股、ETF融资买入、产品内AI分析、预测或自动加池功能。

## 1. 观察池必须由配置决定

### 1.1 不绑定具体ETF代码或固定分组

生产代码、规则、HTML、页面逻辑、测试逻辑及断言中，不硬编码具体ETF代码、名称、管理人、分组名称或固定成员数量。页面可以显示从配置读取的代码和名称；这是配置生成的内容，不是页面中的固定清单。

每只ETF一条配置。初始候选示例不是固定名单，增删成员只改配置，不改业务代码、规则公式和页面。

| 配置字段 | 含义与约束 |
| --- | --- |
| 代码 | 与交易所共同确定基金身份，保留原始格式，不丢前导零 |
| 名称 | 展示名称，由配置提供 |
| 管理人 | 依据正式资料填写 |
| 交易所 | 用于身份、日历和来源路由，不能靠特定代码分支识别 |
| 跟踪指数 | 保存可核对的指数身份，供对应行情展示使用 |
| 所属分组 | 用户可自定义，不要求等于跟踪指数；第一期每只归属一个分组 |
| 启用日期 | 从该交易日起参与观察，包含当日 |
| 停用日期 | 从该交易日起停止参与，不包含当日；未停用留空 |
| 加入依据 | 可定位的持有人披露或官方公告链接，附报告期／段落或页码等定位信息 |

配置缺项或身份冲突应提示原因，不猜测、不静默改用另一只基金。自定义组可能包含不同指数，页面不能据组名推定共同基准，也不能替混合组编造一个“对应指数”。

### 1.2 加入、补历史和停用

- 加入观察池必须由用户确认。可从持有人披露整理含汇金等具名主体的候选及依据，交用户选择；候选不会自动变为启用成员。本轮唯一初始对象已由用户指定，无需重复询问是否选择它。
- 新加入成员先补齐至少321个连续交易日的份额输入，以及相应净值、折算资料等计算必需输入。该数量来自260日展示、此前60日基准及1个份额差分起点，不是321条任意日期记录；若以后配置更长基准窗口，按实际计算需要准备更多输入，不能降低321日的最低门槛。
- 历史补齐并校验前显示“历史不足”，可查看已有单只数据，但不进入观察池或分组合计。成立时间尚短或来源缺失均不能补零凑足。
- 历史补齐状态及首次达标时间由数据检查记录。启用日期已到但历史尚未齐全时，仍不计入；不能把后来补齐的事实倒写为当时已经可用。
- 停用、清盘或合并只设置停用日期，不删除配置、历史数据或历史信号。合并后的基金作为独立身份另行确认，不直接把两只的份额相减或拼接。

### 1.3 配置版本

每次加入、停用或其他影响成员身份、分组、启停范围的修改，均追加观察池版本号、生效日、用户确认记录和变更内容，保留旧版，不原地改写。

实际日度观察按该日有效版本及启停日期确定成员。每次信号保存观察池版本、实际参与名单、排除原因、规则参数版本、输入版本和计算时间。后来的增删不会改写已经保存的历史信号。两种回看方式见第5节。

### 1.4 设计稿与测试的配置要求

未来设计稿使用一份独立假配置作为身份和分组的唯一来源，假序列按该配置生成。HTML、图例、副标题、分组切换和明细表均从配置生成，不能复制一份成员名单到模板或脚本。

测试至少使用两份成员数量或分组不同的隔离假配置；具体样本身份只存在于配置文件，测试从配置读取，不能把真实ETF代码写进测试逻辑。检查项见第7节。

## 2. 数据需求与来源核验

### 2.1 每只ETF的日度输入

| 数据 | 使用要求 |
| --- | --- |
| 数据归属交易日 | 与公告日、获取日分开，按所属交易日历对齐 |
| 日终总份额 | 优先核验交易所清算后披露；保留来源单位和精度，计算不使用界面四舍五入后的“亿份” |
| 单位净值 | 使用同一归属日的单位净值，不能用累计净值或前日净值冒充 |
| 收盘价、成交额、成交量 | 保留价格口径及元、份、手等原始单位，并明确转换 |
| 折算及其他基金事件 | 折算倍率、经核实尾差、分红、申赎暂停、停用／清盘／合并信息及其生效日 |
| 来源与时间 | 原发布方、传输渠道、原文或数据定位、发布时间、获取时间、修订版本 |

份额变化、估算金额、折溢价、比例和信号均由上述输入计算，不把供应商同名字段未经核验直接视为相同口径。

### 2.2 市场环境

复用已验证的对应指数当日及近5日涨跌幅，以及已有市场成交额和相对前20个交易日均值的倍数，只作背景解释，不作为国家队身份判断或异常申赎的必要条件。

市场成交额必须标明“沪深”或“沪深北”等实际范围，同一比较窗口保持一致；不能改名冒充三市数据。三市未就绪不阻塞ETF本身观察，也不自动启动补接北交所。背景缺失单独标注。

### 2.3 持有人披露

从基金半年报、年报中提取前十大持有人：基金身份、报告期末、持有人原名、份额、占比、披露时间、原文链接及定位。随新报告发布更新，不把半年期末当成公开日。

展示“已识别主体的披露持仓”，标明具体主体、报告期与滞后；主体归类依据可查。不把全部机构投资者等同于国家队，不用持仓占比乘日度净申赎金额。未进入前十名表示该表未披露，不表示零持仓；占比下降也不能单独证明持有份额下降。

### 2.4 事件时间线

字段包括事件发生日或区间、发布时间、事件说明、涉及主体及基金范围、来源链接和定位。发生日未知时明确标注，图上使用公告日并写明“公告”。

第一期由用户录入，或由Codex协助整理后经用户确认；不自动抓取。仅宣布增持某类产品、未指明具体基金时，不关联为某只基金的已确认交易。

### 2.5 来源可得性核验

后续获得相应授权后，先做小范围核验，在设计定稿前明确：

- 来源、免费及登录条件、字段单位、公布规律、可得历史深度和持续获取限制。
- 份额与净值各自的归属日期；例如申赎清单的公告日不能直接充当其中净值的归属日。
- 321日输入是否逐日齐全，折算事件能否核对，取得的是当时版本还是最新修订历史。
- 数据缺口、对展示和信号的影响、可追溯替代方案；来源页面存在不等于批量接口已验证。

本稿不承诺固定收盘后更新时间或现有来源已满足全部要求；数据齐备并通过校验后才形成有效计算。

## 3. 计算口径

### 3.1 单只ETF

设当日总份额为S，前一交易日总份额为S前，当日前后折算倍率为f，经核实折算尾差为r，当日单位净值为NAV，收盘价为P。

| 指标 | 定义 |
| --- | --- |
| 可比前日份额 | S前 × f ＋ r；普通日f为1、r为0 |
| 份额日变化 | ΔS = S − 可比前日份额 |
| 份额变化率 | ΔS ÷ 可比前日份额 |
| 日度净申赎估算额 | F = ΔS × NAV；正数为净申购，负数为净赎回 |
| 基金净资产估算值 | S × NAV；不将其日变化当作净申赎 |
| 收盘折溢价率 | P ÷ NAV − 1；价格和净值必须属于同日、同一份额单位 |
| 成交额占基金净资产比例 | 当日成交额 ÷（S × NAV）；不与交易所“换手率”混称 |
| 近5／20日累计 | 对该日期及之前对应交易日的F逐日相加，不用区间份额差乘最后一天净值 |

所有分母必须有效且大于零；必需输入缺失、折算未核实或日期不匹配时，该指标缺失。缺少前一交易日数据不能跨缺口相减。分红本身不直接改变份额，遇折算或其他份额调整按正式资料处理。

第一期不以收盘价代替缺失净值计算正式金额；显示“等待净值／金额缺失”，保留已经能核实的份额变化。成交额、折溢价等辅助字段缺失，不抹掉有效份额数据。

### 3.2 有效ETF与观察池合计

对某个评估日期及所选版本、分组，分别记录：配置中的启用成员数、已达到历史门槛的成员数、当日有效成员数，以及每个排除原因。

**有效ETF**须同时满足：处于该版本启用期内、已经通过第1.2节的历史准入、当日份额差分和同日净值有效，且能够提供规则配置窗口内的历史金额输入（候选60日）。辅助市场背景或折溢价缺失另行提示，不改变份额方向。

观察池／分组合计A为有效成员F之和；全池内同一基金只计一次。组合只按金额汇总，不能把不同ETF的份额直接相加作为统一资金量。

必须同时显示覆盖情况和未参与名单。“历史不足”的新成员按约定不参与，页面注明排除；已达标成员若当日关键数据缺失，只能展示“部分成员金额小计”，不能冒充完整合计或给出完整观察池异常结论。一个有效成员也可显示金额，C2的最低数量要求另见第4节。

### 3.3 缺失、迟到和修订

缺失、等待发布、历史不足、停用、真实零值分别显示。5／20日累计中有应参与但缺失的输入时，完整累计不可用；不得把其余日期之和冒充完整累计。

迟到或更正输入追加版本，重算受影响计算并记录原因；已保存历史信号保留原输入和原结果。当前数据日期、计算覆盖截止日和“数据已齐”的时点分别展示，不用打开页面时间冒充更新。

## 4. 异常观察规则

所有参数由独立规则配置提供。下述60日、2倍标准差、2/3同步比例和连续3日是候选参数，不代表已做历史校准或已获启用；净申购／净赎回绝对下限待回看后由用户确认。

### 4.1 C1：净申赎量级异常

对当日A，以**此前w个交易日、不含当天**的金额计算均值μ和样本标准差σ（分母为w−1；候选w为60）。一次计算固定观察池版本、分组及有效名单，该窗口基准使用同一名单的历史金额重算，避免成员增删本身造成虚假跃变。这段比较基准不冒充过去已经发布的池合计或信号。

- 净申购异常：A ≥ μ ＋ kσ，并且A ≥ L入。
- 净赎回异常：A ≤ μ − kσ，并且A ≤ −L出。
- k、L入、L出为经确认的正值参数，w为不少于2的整数。输入不足不缩短配置窗口；σ为零时显示“历史波动不足，暂不判定C1”，不输出异常或伪造分数。

### 4.2 C2：有效成员同步比例

分母为本次评估范围内有效ETF数量，分子分别为其中份额增加或减少的数量。零变化计入分母、不计入任一方向分子；正负方向分别计算，不设置固定“几只中的几只”。

- **有效ETF不足2只时，C2必须输出“数据不足”。** 不把单只的100%同向当作同步成立。
- 有效ETF不少于2只时，同方向比例达到配置阈值q才成立，候选q为2/3。
- 同时展示有效数量、配置启用数量、分子／分母和排除原因。关键数据缺失导致的小范围比例不能包装成完整观察池结论。

第一期真实配置只有一只，即使历史和金额齐全，观察池同步判断仍为“数据不足”。可继续展示该ETF的份额、金额、C1单项结果及背景证据；不增加另一只来凑数。

### 4.3 市场背景与折溢价

对应指数涨跌、市场成交活跃度和收盘折溢价作为解释信息展示，不作为国家队身份或“已排除套利”的证明。收盘低溢价不排除盘中套利；不保留原稿以单个溢价阈值排除套利的硬条件。

### 4.4 状态和解释

| 状态／标签 | 产生条件 |
| --- | --- |
| 数据不足，未形成完整信号 | 必需输入、历史基准或覆盖不足，或有效成员不足2只；列出全部原因 |
| 规则参数待确认 | 数据条件满足，但本版本必要参数尚未确认；不能当成“未触发” |
| 异常净申购／异常净赎回 | 完整评估条件具备，C1与同方向C2均成立 |
| 未触发异常规则 | 数据、数量和参数条件具备，但未满足上述组合；不是“没有资金活动” |
| 连续净申购／连续净赎回 | 连续N个交易日同方向金额，附天数和累计金额；仅为描述，可与其他状态并存 |

连续标签遇零值、关键缺失或观察池／有效名单改变时中断，缺失不中途跳过；不用“持续国家队入场／撤出”命名。

每条条件输出“成立／不成立／数据不足／不适用”，附实际值、阈值、单位、输入日期、参与及排除名单和版本。主状态不能掩盖仍可查看的单项结果；不输出强弱等级或黑盒概率。

## 5. 历史回看、版本与保留

### 5.1 两种回看方式

| 方式 | 名单与结果的含义 |
| --- | --- |
| 当时版本 | 按当时生效的池版本、启停范围和已保存信号查看，展示当时输入／规则版本；没有保存记录时显示“未记录”，不以当前版本补写成当时结果 |
| 当前版本重算 | 固定当前版本中当前已启用且达标的名单，对所选历史窗口作事后对照，使用明确标注的规则和数据版本；不将当前成员假装为当时已入池，不改旧信号或实际启停日期 |

“当前版本重算”只能使用每个历史计算日及其之前的数值输入；基金成立前、没有可比数据或计算基准不足的日期留空。当前名单及后来补齐／修订的资料只服务事后对照，页面持续标记“当前版本重算，非当时结果”。

两个模式都展示观察池版本号、生效日、参与名单、规则版本、数据版本和计算时间。披露持仓、公告须按实际公开时间区分“当时已知”和“事后对照”；最新披露不能回填成当时已经知道的证据。

### 5.2 回看验证

列出触发日期、方向、金额、条件明细、覆盖情况、对应指数涨跌和事件对照。检查触发频率、连续性及参数变化的敏感程度；留出一段未用于调参的时间作对照，避免专为公告日调整阈值。

没有国家队逐日账户交易数据，不能声称测出了国家队识别准确率。公告日不等于实际交易日，未公告日也不能自动算作误报。阈值修改生成新规则版本及新回看结果，不覆盖原记录。

### 5.3 历史长度与保留

默认展示最近60个交易日，可切换20／60／120／260日；输入按第1.2节准备，展示窗口不是删除期限。新成员准入要求补齐321日，历史逐日计算仍只使用该日应有的差分和基准输入，不能把未来数据带入公式。

已获取真实历史、原始证据、必要版本、固定计算输入、配置版本、历史信号和用户观察记录按项目保留规则保存；不执行原稿“旧数据可丢弃”。只有明确可重建、无保护引用的缓存或隔离假数据可按既有规则清理；本稿不授权迁移或删除。沿用本地数据150GB软上限。

## 6. 页面与设计稿
