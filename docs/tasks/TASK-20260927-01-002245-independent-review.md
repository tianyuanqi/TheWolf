## 6. 问题格式、级别与通过条件

每条发现：`R01 / P级 / 类别 / 文件:行号 / 触发条件 / 预期与实际 / 影响 / 复现或代码依据 / 最小修复建议 / 关闭条件`。行号以待审提交为准。类别明确为已证实缺陷、待验证疑点或非阻断建议；严重性和证据置信度分开说明。

- P0：严重安全失控或数据破坏，立即阻断交付。
- P1：关键金融错误、权限失效、核心恢复失败，修复并独立复核后通过。
- P2：有实际影响的局部行为/可靠性问题，修复或由用户明确接受延期、影响及处理计划。
- P3：非阻断的维护性建议；不因个人偏好要求无关改版或重构。

允许结论：需要修改、审查受阻、通过（可附非阻断建议）。无 P0/P1；P2 已修复或明确接受；关键验证缺口已解决，才可判通过。来源五年能力、分发包等范围外问题不能不加区分地阻断本切片。未发现缺陷时明确写“在所审范围未发现可证实缺陷”，同时列残余风险和覆盖局限。
