# TheWolf 总体方向与分步开发计划 V0.1

修订：2026-10-04。依据用户要求“划定总体方向，拆分可独立完成的步骤，先不执行，以后的开发任务按照文档目标进行”。本文件沿用原路线图路径，作为后续开发的统一计划入口；不另建并行路线图。

范围与产品含义以 [PRD](PRD-V0.1.md) 为准；本文件维护目标分解、顺序、依赖和阶段完成条件。当前授权、进展、开放问题只在 [status](status.md) 维护，具体执行约定按 [Task-Workflow](Task-Workflow.md) 在任务启动时形成。本文不是生产代码实施任务书，也不授权执行表中步骤。方向讨论稿 v0.4、文件名 V0.1 与计划步骤编号均不代表软件发布版本。

## 1. 总体方向与执行原则

TheWolf 面向个人中长线投资者，围绕收盘后观察、公司研究、投资论点记录、决策和复核逐步形成可解释、可追溯的投资流程。产品包含相互连接的两个领域：市场、行情、公司与资料支持；投资论点及其演变。市场总览是默认首页，投资论点是核心研究对象。

用户已确定顺序：**先完成第一批市场与指标看板，再做论点—决策—复核闭环**。第一批完整范围由 PRD §5.1–5.2 定义，不能交付少数容易获取的指标后宣布整批完成。

- 沿用现有桌面、Python 本地服务及存储路径，从已验收的单股日线/公告切片演进；按实际源码判断复用位置，不预先建设完整平台或更换技术栈。
- A 股与港股为主要观察市场，海外与商品提供外部环境。按日线/月度等实际频率保存，所选历史最终目标至少五年，默认不滚动删除；具体保留边界以 PRD 为准。
- 每步交付一个可检查、可演示或可复用的结果。开发步骤尽早贯通数据、计算与界面，不先建完所有后端再开始集成。
- 时间、单位、来源、版本、固定输入、失败恢复与离线读取从各序列首次接入落实。数据缺失不能补零，最新修订历史不能冒充当时可知证据。
- 指标帮助观察和提出问题，不合成黑盒买卖结论。真实案例用于验证使用价值，不以一次盈利证明投资方法有效。
- 不预设交付日期、固定工时或未经实测的性能数字；需要时在具体任务中依据数据量、设备和风险确定。

详细序列、公式、页面与状态建议引用 [看板设计](Market-Dashboard-Design-V0.1.md)，来源能力与风险引用 [Data Sources](Data-Sources-V0.1.md)，不在计划中重复维护另一份口径表。

## 2. 步骤总览与依赖

“可独立完成”指：满足本步必要输入后，能独立形成交付和验收结论，不必等整个产品做完；不表示步骤之间没有依赖。以下编号是稳定的计划标识，区别于历史 T/S 编号和未来 `TASK-YYYYMMDD-NN` 任务编号。

| 顺序 / ID | 独立交付目标 | 必要依赖 | 阶段完成时应能看到什么 |
|---|---|---|---|
| PLAN-P01 | 分组验证真实数据来源 | 已确认首批范围；明确本次隔离验证边界 | 来源样本、字段/历史能力证据及逐项缺口处置建议 |
| PLAN-P02 | 按模块确定口径、交互和实施边界 | 对应 P01 分组结果、现有设计建议 | 该模块有足够具体的设计与验收依据，待定项没有冒充已确认 |
| PLAN-M01 | 单个指数贯通真实看板流程 | 所选指数来源验证、对应 P02 约定 | 从获取、保存到页面、解释、离线及更新失败恢复的完整小切片 |
| PLAN-M02 | 补齐 A/H 指数与长期价格视图 | M01；其余指数来源和对应 P02 | 全部已选指数可看实际历史、区间表现与覆盖情况 |
| PLAN-M03 | 市场涨跌分布与成交活跃度 | M01；P01-A、对应 P02 | A 股集中涨跌区及 A/H 各自的成交强度，统计范围可核对 |
| PLAN-M04 | 指数估值与股债比较 | M02 的身份/价格入口；P01-B/D、对应 P02 | 估值、历史分位、收益率与国债比较可复算且解释清楚 |
| PLAN-M05 | 资金成本与货币融资看板 | M01；P01-D、对应 P02 | DR007/政策利率、HIBOR、社融/M2按各自频率与时间语义展示 |
| PLAN-M06 | 商品、汇率及海外利率看板 | M01；P01-C/D、对应 P02 | 已选公共环境序列可长期查看、比较、追溯来源与口径 |
| PLAN-M07 | 自选与公司基础工作台 | M01；P01-A 的重点证券子范围、对应 P02 | 用户能管理有限关注名单、看基础行情/已有资料，取消关注仍保留历史 |
| PLAN-M08 | 首批看板整体验收与日常使用衔接 | M02–M07 | 首批范围逐项有真实验证结论，组合、更新、离线和恢复可一起使用 |
| PLAN-R01 | 论点流程与低成本录入 Demo | M08 完成并取得用户阶段验收 | 一个真实想法能走通记录、决定和复核的交互，确认最低必要字段 |
| PLAN-R02 | 论点与决策快照持久化 | R01 的确认结果 | 原话、论点、依据、个人规则/状态与用户决定可固定保存和重开 |
| PLAN-R03 | 日期/手工复核及论点闭环验收 | R02 | 同一论点至少完成一次决定与一次复核，前后理由和版本可对照 |

默认按表推进。P01 各分组可分别完成；P02 随对应模块逐步收敛，不要求一次定完全部未来设计。M03、M05、M06、M07不依赖彼此完成；在相关来源与约定齐备后可以调整先后。M04与M02可按已经就绪的指数子范围衔接。调整不能遗漏首批范围，也不自动启动并行 Agent 或多个写入任务。

早期优先调查五年估值、铜连续序列和市场统计等高风险来源。某一来源受阻，不阻塞其他已授权、确实独立的步骤；但该缺口仍属于首批完整交付的未完成项，不能因此提前进入论点阶段并宣称看板完成。改变整批范围或“看板先行”的阶段顺序须由用户决定并更新计划。

## 3. 准备步骤

### PLAN-P01：真实数据来源验证

**目标**：证明将要实现的功能有可靠输入，区分页面能看到、样本能获取、历史能覆盖和更新能持续四种不同能力。

按下列分组独立交付结果；它们是 P01 的子步骤，不是一次性下载全部数据的指令。

| 子步骤 | 验证对象 | 应交付的依据 | 影响的后续步骤 |
|---|---|---|---|
| P01-A | 已选 A/H 指数价格，A 股涨跌统计、A/H 市场成交，以及用户选定证券的基础行情 | 身份/收益类型、市场与证券范围、单位、日历、更新完整性、历史访问方式；涨跌停规则与成交统计可对账 | M01、M02、M03、M07 |
| P01-B | 各已选指数 PE-TTM、PB、股息率与历史 | 盈利/股本/亏损处理方法、可用起点、频率、五年覆盖能力；不同渠道是否同口径 | M04 |
| P01-C | 上金所金银、COMEX 铜、布伦特、USD/CNY | 对应价格类型、单位、时点、历史获取；铜底层合约和连续规则；访问条件与许可限制 | M06 |
| P01-D | 中国/美国国债收益率、DR007、政策利率、HIBOR、社融与M2 | 期限/类型/频率、发布日期与修订、可用历史、日历和更新延迟 | M04、M05、M06 |

执行前为本次分组明确代表序列、日期/月份、必要边界样本、请求与文件限额、隔离目录和恢复方式。先验证少量真实样本，再按明确范围检查长历史；完整五年覆盖可随对应功能步骤继续验，但最终验收前必须有证据。一次成功请求不能证明持续可用或完整覆盖。

**交付物**：在来源文档维护能力结论，必要时链接独立验证报告/原始样本；给出“序列—字段—期间—限制—后续方案”。所有结论保留验证方式和日期，访问失败与语义不匹配分别记录。

**完成条件**：分组内每项都有可核对的样本与能力结论，或明确不可得证据和替代建议；适用来源可与官方口径或可靠原始资料对账。验证步骤可以以“发现不可行”结题，但不可行项不能被当作下游功能已具备，需保持开放处置。

**范围外**：付费采购、绕过限制、正式库写入、无边界五年批量回填、全市场个股长期采集。验证暂存与正式产品数据分开。

#### P01首轮已确认范围：沪深300

2026-10-04 用户确认“沪深300，价格验证＋估值来源摸底”。本轮选定 P01-A 的单指数价格子范围及 P01-B 的同指数摸底，不代表两个分组整体完成。

- **价格主线**：验证沪深300价格指数的日期、开高低收、昨收或相邻交易日收盘、来源与获取时间。近期样本以执行验证时上海时区当前日期为基准，按交易日历倒推最近260个完整交易日；当天已收盘且来源完整性校验通过时包含当天，否则从最近完整交易日起算，为核对20/60/250日涨跌幅预留输入；缺失不得用更早数据静默补足。取样截至日按执行时交易日历及来源完整性明确，不因当前日期推定已齐全。
- **历史摸底**：抽查约五年前及中间年份的代表区间，核对历史入口和字段一致性。抽查成功不等于完整五年覆盖；连续覆盖检查留待有明确边界的后续回填，最终至少五年目标保持。
- **估值辅线**：核查同指数 PE-TTM、PB、股息率的定义、可取期间、频率和访问条件；区分实际样本与文档宣称，不在本轮实现估值计算或页面。
- **失败重试**：每个确定的接口请求（来源、参数及分页相同）首次失败后最多重试10次，即最多11次尝试；成功即停止重试。第10次重试仍失败，停止该请求及依赖它的采集步骤，不发起第12次尝试，不通过换进程或重复启动自动重置计数。报告失败来源、目标区间/分页、实际尝试次数、可核实的错误原因和未完成影响；原因未知时如实说明。重试间隔、超时及来源限流要求由Agent按接口约束确定，避免连续无间隔请求；总请求预算须另计全部分页和重试，10次不是数据条数或整个任务的总调用数。本条属于首轮验证约定，不表示既有002245更新已增加自动重试。
- **测试数据归属**：本轮样本和需要的测试库放在测试环境的本任务独立数据根，沿用现有QA隔离机制；日常正式根保留给用户使用，不写入、不切换、不导入测试结果。当前QA入口接受显式隔离目录，没有一个固定共享测试库；实际路径在执行前确定并记录，不复用其他会话的数据目录。仅接口验证无需启动桌面；若需桌面验证，使用现有QA入口指定独立端口和应用标识。结束后按现有规则恢复临时运行影响，保留必要证据及重建步骤。
- **执行方案**：实际来源候选、代表日期规则、含重试的总请求预算、文件限额、测试数据根及恢复约定见[来源验证方案§8](Data-Sources-V0.1.md#8-沪深300首轮来源验证执行方案)。执行时先核验日历并固定实际请求清单及日期；免费来源优先，小样本验证。方案编写不自动批准接口调用，也不表示来源验证已完成。
- **交付与衔接**：按本节既有证据要求报告可得字段/期间、对账、历史与更新限制、未解决项及关闭条件。价格验证具备证据后可进入该指数 P02；估值缺口单独保留，不把价格通过算作估值可用，一次获取成功不算长期稳定。
- **后续分组**：铜连续序列、市场统计仍按高风险来源优先安排后续验证，不因首轮聚焦而从首批需求删除。

### PLAN-P02：按模块固定开发依据

**目标**：让接下来的一步具备足够清楚的实现约定，不提前设计全部模块。

**工作与交付物**：结合对应 P01 结果及当时实际源码，确定序列身份、字段、单位、时间与版本、指标输入/公式、完整性与缺失处理；明确页面导航、状态、组合方式和验证窗口。只细化本模块所需的 API、存储兼容和失败恢复，引用现有架构/数据模型并记录必要调整。

**完成条件**：相关设计文件中能够定位已确认选择、剩余假设、验收例子和现有能力的差异；影响该步业务含义的关键歧义已解决。当前看板设计 §1/§5 的候选序列、更新和布局不会仅因进入本计划自动获批；公式核查、接口参数与常规实现选择由 AI 处理，不让用户承担技术调查。

**范围外**：完整 Thesis schema、通用可视化平台、全产品数据库迁移和全部代码任务书。P02按模块完成；不成为要求所有设计一次冻结的额外审批流程。

## 4. 首批市场与指标看板

### PLAN-M01：单个指数的真实端到端切片

**目标**：在现有软件中先打通一条新看板流程，检验新的数据与页面是否能一起工作。

**阶段数据边界**：按[PRD历史阶段约定](PRD-V0.1.md#53-历史频率与保留)先使用已验证的260个交易日推进沪深300P02、M01任务书及首版开发验收；无需先完成五年覆盖、补齐2021/2023抽查日历或修复本轮历史请求。五年价格回填与连续覆盖由M02承接，五年估值由M04承接；这些最终要求保留，历史报告中的未通过结论不删改，也不升级为当前M01阻塞。

**范围与交付物**：首个对象已确认为沪深300，须在来源验证后形成受控获取、不可变来源依据、本地保存、最近完整数据读取、数值摘要与日线蜡烛图、日期筛选和必要解释；具体交互及验收引用[设计§5.5](Market-Dashboard-Design-V0.1.md#55-首个指数切片已确认约定2026-10-04)。选择足够检验窗口计算的隔离样本；未取得的长历史明确标为未完成，不用模拟数据冒充来源接入。仅扩展这条路径必须的身份、日历、时间、存储/API和可复用组件。

**完成条件**：真实来源样本与页面值对得上；点开来源/计算可定位固定输入；保存后断网可读；更新无变化、失败和中断均有可观察结果，重启只见完整版本；既有单股/两公告阅读及原更新行为无非预期回归。包含受影响自动检查、真实界面检查和用户演示。

**边界与恢复**：仅在对应约定确认后改变更新行为，尤其不能顺带将既有单股的“不含当日”改掉。测试使用隔离根，失败保留上一有效版本；不以这一切片宣称首批看板完成。

### PLAN-M02：全部已选指数与长期价格视图

**目标**：用户可以在市场总览比较 A/H 指数并查看指定历史区间。

**范围与交付物**：补齐 PRD §5.1 已选指数；提供价格、20/60/250交易日表现、五年走势与距离所选窗口最高收盘价的跌幅。完成对应来源适配、历史回填和后续更新能力，逐序列展示覆盖、回溯历史及实际起点。

**完成条件**：逐指数对账身份、单位/收益类型、预期交易日与真实覆盖；长历史可按时间筛选，已保存记录不因窗口变化滚动删除。窗口端点、缺数和历史不足反例通过；成立不足五年的序列按客观起点说明，不伪造更早历史，也不将其他来源缺口解释为该例外。

**边界与恢复**：不采集全部个股、不把指数成交额加总成市场额。价格历史达标不代表估值历史达标；分段回填可恢复，失败不破坏已发布区间或旧证据。

### PLAN-M03：涨跌分布与成交活跃度

**目标**：收盘后能够看清市场上涨覆盖面、极端收盘分布及相对成交水平。

**范围与交付物**：A 股上涨/下跌/平盘、收盘涨停/跌停及上涨占比集中展示；A/H 分别展示明确统计范围和币种的成交额、前20交易日均额与相对倍数。优先利用口径可靠的汇总；确需截面计算时限定当日统计所需数据，不由此建立全部个股长期行情库。

**完成条件**：代表日统计能够对账；证券范围、停牌/缺失等排除可解释；涨跌停不固定按10%判断，不重复计入分母；前20日均值不含当日，未知缺数不跳过补齐；A/H 不混币种或范围。数据缺失、未就绪与正常零家数可区分。

**边界与恢复**：不建设港股涨跌停制度的错误类比，不将成交额称为净流入。统计规则有版本，更正追加依据，旧引用仍固定可读。

### PLAN-M04：估值与股债比较

**目标**：把价格位置与估值位置区分开，并让股债比较的输入和局限可见。

**范围与交付物**：逐指数补齐同口径 PE-TTM/PB 和实际五年分位；接入适用的股息率及中国10年国债序列，展示盈利收益率差、股息收益率差和获确认的比值切换。复用 M02 已就绪的指数入口；先后顺序按核实后的适用性确定，不省略未就绪指数的需求。

**完成条件**：每个字段有来源方法与历史覆盖证据；公式和同日输入可复算；负PE、不适用值、零分母、重复/缺数、跨日和修订反例通过。五年分位显示实际期间和有效样本，残余缺口是否满足验收在来源结果明确后确定，不能以任意覆盖率自动放行。

**边界与恢复**：缺失提示是正确失败行为，不等于核心指标交付通过。港股保留适用估值，不直接套人民币国债作股债比较；不输出“低分位必涨”。新计算固定算法和输入版本，来源/公式变化不改写旧结果。

### PLAN-M05：资金成本与货币融资

**目标**：分别观察短期银行间资金成本和货币/融资增长，帮助用户理解各自说明的环境。

**范围与交付物**：DR007与7天逆回购政策利率同图，香港一个月HIBOR独立展示；社融存量同比与M2同比按月同图，并提供确认后的差值。每项带原始序列、定义、用途、局限和时间说明。

**完成条件**：期限和利率类型正确；政策利率有效区间不被误当每日新观测；社融/M2同月计算，统计月份与发布日期可区分。历史覆盖与修订局限逐项核实，月度数据不插值为每日观测、发布前不冒充当时可知；日/月视图、缺数及重启离线读取有验证。

**边界与恢复**：不将增速差换算为即将流入股市的金额；不扩充全部宏观数据库。不同来源部分失败时保留各自有效版本，组合计算固定日期与版本。

### PLAN-M06：商品、汇率与海外利率

**目标**：让已选公共序列成为可长期观察和搭配的外部环境看板。

**范围与交付物**：上金所金银、COMEX铜、布伦特、USD/CNY、美债10年/30年；采用对应 P02 明确的具体价格类型与时点。支持历史筛选、原单位展示及经确认的比较方式，标注各自交易日期、时区和更新延迟。

**完成条件**：逐项完成真实值、单位、字段、时间和历史覆盖核对；铜连续规则/底层合约可追溯，换月可见；基准价不伪造OHLC，缺失不拼接其他价格类型；跨币种比较清楚说明归一化含义；长期查询、缺数、部分更新失败和离线均验证。

**边界与恢复**：不把期货连续价格变化当作持仓收益，不自动采购许可或另换铜/原油品种。来源不足交回具体方案；切源需兼容核验并保留原版本。

### PLAN-M07：自选与公司基础工作台

**目标**：用户能查看真正关注的证券，减少基础研究时切换应用的需要。

**范围与交付物**：由用户定义的有限自选/主要行业龙头/研究证券名单，基础行情和历史区间视图，既有公告/原件阅读入口。明确证券身份、个股复权比较以及各类关注关系对更新范围的影响；新增证券所需资料获取另按具体范围约定，不默认下载全部公告。

**完成条件**：关注证券身份与真实价格对账，历史覆盖和复权口径清楚；增加、重复关注、取消后重开等流程可验证。取消自选不删除历史/原件/引用，其他有效关注原因不会误停；既有两份公告仍能离线打开。

**边界与恢复**：不自动选龙头、不建全市场长期个股库、不实施完整财务拆解、同行研究平台或交易账本。名单变化与数据保留分开处理，失败不改变既有有效内容。

### PLAN-M08：首批看板整体验收与日常使用衔接

**目标**：把独立模块整合成用户能日常使用的第一批完整看板。

**范围与交付物**：检查导航、来源详情、统一时间筛选、经确认的组合模板与更新状态在各模块的实际使用。逐项关联首批范围、实现版本、来源覆盖、测试/界面证据和未完成项；材料按现有任务/报告归属保存，不另建永久状态台账。

**完成条件**：下方范围映射逐项满足验收；用户能从总览查看表现、区分价格/估值/资金环境、打开解释和依据、组合已选指标、断网重开已有数据。跨市场日期、来源部分失败、缺数、窄窗口/键盘、长历史查询、引用保护和恢复路径实际验证。基于目标设备测量资源与响应，涉及150 GB软上限时提出实际方案，不擅自清理历史。

日常使用衔接需明确新旧数据位置和更新行为；如涉及正式库启用或迁移，按对应授权先完成一致性备份、隔离恢复与兼容验证，再执行获准操作。不能将测试目录直接切成日常根。开发完成、验证通过、用户验收分别记录；仍有核心来源缺口时保持部分交付，范围取舍须由用户明确决定。

**边界与恢复**：本步骤不要求最终分发安装包、云部署或全自动调度。保留既有可用切片及恢复入口，不把代码回退当作数据恢复。只有首批整体验收完成，或用户明确调整阶段边界，才进入后续论点阶段。

## 5. 论点—决策—复核阶段

### PLAN-R01：真实案例与低成本录入 Demo

**目标**：先验证用户愿意使用怎样的论点流程，再固定持久化实现范围。

**输入与交付物**：首批看板阶段结果和一个用户选择的真实关注问题，优先考虑已有持仓再评估。用交互 Demo 走通原话、理由、时间窗口、重新考虑条件、信心、少量遗漏问题、最终决定和复核。允许未知与跳过，AI整理与用户表达明显区分；回忆补录不能冒充当时记录。

**完成条件**：用户能够完成并回看一条案例，明确哪些输入必要、哪些系统辅助以及哪些可以以后再补；形成最低登记条件、状态转换、决策快照和复核交互的设计依据。记录真实录入负担与困惑，由用户判断可接受程度，不预设成功率或秒数。

**边界**：Demo 可使用明确标识的演示内容，不宣称已有长期保存或到期监控。个人规则值、复核周期和AI接入程度在本阶段明确；不要求用户填写完整对象关系图或先导入交易账本。

### PLAN-R02：保存论点版本与决策快照

**目标**：可靠记录“当时怎么想、依据是什么、最终怎么决定”，并与现在的分析分开。

**范围与交付物**：按R01确定的最小模型持久化原话、结构化论点、必要子问题、证据/反证/未知、信心和论点版本；保存用户决定及对应数据输入、个人规则版本、资金/持仓暴露等必要状态快照、备选与不操作、AI分析和下次复核时间。原始记录受保护，修改追加版本。

AI先做有边界的辅助结构化和遗漏提醒；如接入远程模型，先明确连接、发送资料范围和费用约束，AI分析不进入独立外部证据池。无模型时手工记录、资料查看和确定性分析仍可使用。

**完成条件**：重启/断网后可找回当时原话、来源和用户决定；修改新论点、新规则或最新行情不改变旧决策。可登记买卖、继续持有、研究后不买等约定决定；更正、缺字段、保存失败/中断和引用保护验证通过。个人信息只保存本阶段必要内容，不把组合规则检查演变为自动交易指令。

**边界与恢复**：不先建完整研究平台、账户账本或全部监控能力。存储演进先验证旧库兼容与隔离恢复，正式迁移单列影响与授权。

### PLAN-R03：复核与闭环验收

**目标**：用户能够对照旧决定重新研究，并保留判断变化的过程。

**范围与交付物**：到期列表与手工复核入口，对照旧论点、关键判断、支持/反对证据及未知，记录维持、修改、放弃或继续研究的理由，形成版本时间线与下一次复核。复核引发新的投资决定时另存决策快照。

**完成条件**：同一个真实案例跨至少一次决定和一次复核；可以分别找回AI当时分析、用户决定和后来修改原因，旧记录不被覆盖。日期/时区、未到期、逾期、重复提交、中断和重启路径有验证；用户能说明该流程是否帮助回忆、发现遗漏并降低记录负担。

体验证据与长期效果分开：先观察理由可找回、反证被记录、复核能持续使用；长期再结合多次案例评价过程改进，具体尺度由试用共同确定，不用单次收益给过程质量打分。

**边界与恢复**：早期到期列表不等于后台推送、常驻任务或全自动变量监控；不实施完整交易收益复盘。复核与更正追加记录，失败不能覆盖旧决定。

## 6. 后续方向与计划调整

论点闭环经过真实使用后，按实际问题选择下一阶段：可稳定获得的变量监控、手工变量补充、反证与竞争解释、论点相关视图、必要财务或行业研究。自动、手工和不可观测变量分别处理，不假定联网AI能获得所有关键事实。

交易导入、收益核算、事件研究、历史回测以及最终分发打包只作为后续候选，不设置当前执行步骤或日期。它们不构成当前看板或决策记录的前置条件；自动交易、无依据荐股、全市场无差别归档等仍按 PRD 排除。

修改计划时说明新证据、影响的步骤/依赖和保留的验收，不静默移动目标。单个来源或步骤发现问题，先处理对应范围；不因局部困难重新启动整个项目。既有任务约定、审查结论和修复计数继续保留。

## 7. 后续开发任务如何使用本计划

1. 新任务先读取规则与 status，再定位本文件的具体计划 ID；明确这次承接哪个目标、哪一部分、依赖是否已有可复用证据。按本文目标安排后续开发，不从历史T/S目录自动启动任务。
2. 开发前读取相关实际源码与适用规范，形成当前版本上的实施约定；需要交接时按 Task-Workflow 生成任务书。任务书注明“所属计划步骤、交付子范围、验收映射、排除项”，不能只引用一个大阶段名称。
3. 一个步骤可拆成多个有限代码任务；每个任务须有独立验证结果。修复/维护任务关联所保护的原步骤或已验收能力，不因追求路线覆盖增加无关功能。
4. 常规实现选择在已授权范围内自主处理；影响产品含义、首批范围或重要数据策略的选择先明确。详细任务评估、执行模型/档位建议及审查方式在任务形成时按流程处理，本计划不固定模型、并行人员或自动往返。
5. 交付按README验证入口选择检查，补充真实来源/界面/恢复证据，关联代码版本与未提交增量。测试结束核验环境恢复；任务完成不等于所属计划步骤整体完成，步骤完成不等于整个产品完成。
6. 当前授权、进展、缺口与下一步只更新status；产品范围变化更新PRD，顺序/依赖变化更新本文，技术约定变化更新对应设计。已经确认且未变化的内容不重复询问。

首次执行应从 PLAN-P01 的有限验证范围开始，并在具备相关结果后按模块推进 PLAN-P02；本轮只记录计划，不执行验证、开发、迁移、批量采集或发布，也不预建全部开发任务书。

## 1. 版本路线图

### V0.1 — 可信的市场与公司研究闭环

目标：日常看市场，深入研究少数公司，每个重要结论能回到资料或计算依据。

In Scope：沪深京日线/基础指标/主要指数、当前一级行业成交分布、状态描述、全市场公告增量索引、重点公司 L3 归档、中文检索与证据卡、My Focus、单助手只读工具、国家统计局与央行各一类官方发布、版本化存储、PIT 框架、任务恢复、空间预算、当前 macOS 桌面运行。

Out of Scope：完整海外证券库、全球行情面板、完整宏观序列库、自动财务附注结构化、历史事件研究、复杂估值与自动企稳评分、交易导入及所有 PRD 排除项。

依赖：可用的来源权限；核心日线覆盖、官方索引路径、证据定位与本地打包验证；不存在必需云服务。

验收：PRD A01–A10 全部通过；实际来源接入及历史覆盖达到约定范围；PIT 不可用项明确禁用；连续 10 个交易日任务观察及至少一次周末公告更新检查；故障恢复和空目录恢复通过。演示数据可用于开发，但不能代替真实来源验收。

### V0.2 — 公司基本面与外部环境

目标：能围绕行业受益、收入来源和公司类型做有时间约束的深入比较。

In Scope：重点公司基础财务及收入分部结构化、分红与稳定型/成长型 valuation profile、验证后的行业历史、宏观核心序列及修订、少量全球环境指标、更多官方政策栏目、资料增量对比。需要时引入 OCR 和语义检索，但只有实测增益明确才实施。

Out of Scope：全市场财报附注无差别深抓、完整跨市场交易、自动下单、无依据的“龙头识别”、机器学习预测、多 Agent。

依赖：V0.1 证据/时间/同步稳定；结构化财务、行业历史、宏观及全球序列的权限、定义和 vintage 能力逐项验证。

验收：至少 1 家稳定型与 1 家成长型公司的关键财务值可回到报告；期间/币种/合并范围一致；重述版本测试通过；已选全球指标没有跨时区未来数据泄漏；每个 profile 对缺失指标明确降级。宏观数据库最新值与原始发布值不混淆。

### V0.3 — 可复现的历史研究

目标：验证“持续下跌、企稳、过热”等状态与后续路径的历史关系，避免把偶然样本当成规律。

In Scope：版本化描述性筛选、股票比较、条件统计、事件研究、历史成员与退市样本、规则参数研究、报告复现；展示样本数、分布、失败案例、窗口选择和多重比较局限。统计工具输出研究结果，不输出交易指令。

Out of Scope：实时策略执行、自动最优参数选股、大规模机器学习平台、将历史收益包装成预测承诺。

依赖：研究窗口内真实 PIT 数据和足够样本；若某系列只有 latest_revised，只能用于明确标注的事后研究，不进入严格历史验证。

验收：每个研究可凭输入清单、参数和代码版本重放；验证集与探索集分开；覆盖幸存者偏差、前视偏差、事件时间对齐和重叠样本；至少一项状态研究有正反例与敏感性结果，无“通过挑参数获得确定买点”的产品结论。

### V1.0 — 可长期维护的个人研究工作台

目标：低维护成本、连续积累数据、稳定完成日常研究。

In Scope：稳定发布与迁移、长期备份恢复、资料与状态变化回顾、研究项目归档/导出、来源健康管理、按需求补充平台打包；可选历史交易导入与行为复盘（平均持有时间、买后回撤、逆势抄底、盈亏持有差异），仍无交易执行。

Out of Scope：SaaS、多用户、支付、社交、券商执行和自动荐股。交易导入不扩成完整会计/税务 Portfolio 系统。

依赖：V0.x 核心流程稳定、数据源授权持续有效、真实使用反馈。交易行为分析单独依赖可解析且去重正确的交易记录。

验收：连续 30 日运行记录可解释；至少一次版本升级/回滚与完整恢复演练；保护数据在空间清理后仍完整；研究与证据可导出。如果交付交易导入，原记录与规范化交易一一追溯，费用/拆合股/持仓未平仓等边界有测试，不对不完整账户历史输出伪精确收益。

### 2.1 首个真实流程切片

范围：一小批真实日线和一份官方公司公告 → 本地保存 → 页面查看 → 点击原始证据 → 中断后恢复。首批样本、日期范围和来源由本轮能力验证确定并记录，不使用虚构金融数据冒充真实接入。

前置条件：有明确实施授权；来源可在已有权限内访问；隔离的数据根；页面框架、导航、状态、视觉方向和公共组件约束已形成可追溯的本轮设计依据。涉及重要产品歧义先解决，常规实现选择无需重复审批。

|---|---|---|---|
| S01 | 最小来源/运行验证，取 T01–T04 与 T05 中该流程必要部分 | 使用真实来源取回样本，记录权限、原始单位、来源/发布时间；本地服务和页面能启动 | 隔离暂存可清理，不改用户数据 |

首个切片不要求完整定时调度、中文全文检索、所有行业/指数、全市场回填、AI 回答、完整研究项目管理或最终桌面安装包。页面可先在本地 Web 开发入口验证；需保留 Tauri 最小运行验证，最终桌面交付仍按完整范围验收。只要提供本地 API，从切片开始就落实访问与文件路径边界，不把安全保护留到最终打包。

切片验收采用真实接口与隔离数据、确定性测试、故障注入和实际界面检查；用户演示确认另行记录。未经实测不写“验证通过”。

规划量级：单人持续开发约 8–12 个有效工作周，另含至少 10 个交易日观察期，可与后期完善部分重叠。这只是排程初估；数据权限、网页变化、打包和财报解析可能改变成本。完成 M1 后按实际数据量和问题重新估算，不承诺固定交付日期。

## 4. 发布门槛与不允许的“假完成”

- **数据门槛**：历史起点、市场范围、字段/证券覆盖、退市/停牌处理有实际报告。必要市场/字段缺失不能被“接口已接入”掩盖。
- **时间门槛**：新抓到的后续修订值不会泄漏到旧 as_of；历史不足明确降级。无法重建所有过去不阻碍如实发布，但不能宣称完整 PIT 历史库。
- **证据门槛**：关键事实引用完整；人工金标检查无关键无依据事实；概念与收入的案例通过。
- **可靠性门槛**：强杀、限流、断网、低空间与恢复测试通过；原子清单和引用保护不可关闭后宣布完成。
- **产品门槛**：用户能完成市场→公司→原件→研究报告全流程；无模型时仍能研究资料；没有 BUY/SELL 自动结论。
- **运行门槛**：目标机器性能测量有记录，桌面包可重复启动、退出、离线使用；不把仅开发服务器可用等同桌面完成。

若核心来源权限导致达不到原范围，应提交“缺失能力、影响页面/工具、替代来源、费用与修订验收”具体差异表，由用户决定范围或来源。不能静默把北交所、退市数据或证据系统删掉以缩短工期。
