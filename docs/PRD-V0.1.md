# PRD V0.1

日期：2026-09-18。状态：待用户确认。配套：[架构](Architecture-V0.1.md)、[执行计划](Implementation-Plan-V0.1.md)。

本地数据保存范围的细化建议见 [A 股大盘与个股数据](Local-Data-Scope-V0.1.md)，不改变本提案的待确认状态。

## 1. 产品定义与成功标准

Personal Market Intelligence 是个人投资研究工作台。主要服务持仓通常不超过 3 个、可能集中持仓、持有期常超过一年的 A 股投资者。

产品要解决的核心问题是：**把“价格跌了很多”与“有足够证据值得进一步关注”分开；把“市场叙事”与“公司已经披露的业务事实”分开。** 系统展示状态、历史比较和证据，不替用户作出交易决策。

研究链路：全球环境 → 中国宏观 → A 股市场 → 行业/板块 → 公司 → 入场与离场辅助。全球指标是 A 股研究的外部环境输入，不建设完整海外证券库。

产品成功不以交易收益、荐股命中率或预测涨跌衡量。V0.1 的成功是：用户能看懂最近一个完整交易日的市场状态；能为一家公司建立可持续更新的资料档案；能从关键结论点击到真实证据；数据不完整时系统明确说出不知道。

## 2. 产品原则

- 数据层不依赖界面；分析层不依赖模型；AI 不提供金融事实。
- 当前状态与历史可知状态明确分开；缺失、过期、不适用、未披露不当作零。
- 估值、趋势、成交、基本面分开展示，V0.1 不合成单一“投资价值分”。
- 成交额和成交占比描述交易活跃度与集中度，不能直接称为资金净流入。
- 公司、行业分类和市场概念分层；概念标签只能引导检索，不能证明真实业务。
- 原始事实、计算结果、研究推断和用户观点有不同视觉标记。
- 离线可以阅读已同步的数据、文档和已保存报告；增量同步需要联网。AI 是否能离线取决于后续配置的本地模型。

## 3. 关键用户流程

| 流程 | 用户动作 | 系统输出 | 不足时的行为 |
|---|---|---|---|
| 日常观察 | 打开市场总览 | 最近完整交易日成交额、趋势、宽度、主要指数、行业成交集中度 | 保留上一完整快照，展示待补齐日期与缺口 |
| 防止过早抄底 | 打开关注公司 | 价格位置、历史估值、趋势、近期新低、成交状态并列 | 没有历史估值样本时不计算分位，不给入场结论 |
| 研究热点公司 | 创建研究项目，输入业务问题 | 主营与收入证据、概念相关证据、已披露程度、未知项 | 没检索到证据写“当前资料未找到”，不能写“没有此业务” |
| 观察过热 | 查看股票及所在行业 | 涨幅、成交额与换手率历史位置、行业占比变化 | 数据不齐或阈值未验证时只给数值比较 |
| 追踪变化 | 打开 My Focus | 当前持有/重点观察/正在研究/已研究，新增官方资料、研究更新时间 | 不把新公告自动解释成利好或利空 |
| 历史回看 | 指定日期与信息截止时刻 | 符合时间条件的数据和资料，PIT 覆盖说明 | 历史版本缺失时返回不支持或明确降级；不能混入后来修订值 |

V0.1 的历史回看限于行情、资料检索和基础指标；完整事件研究、策略回测属于后续版本。

## 4. 信息架构与页面

### 4.1 市场总览

顶部固定显示：市场日期、信息截止时刻、同步状态、覆盖率、当前/历史模式。首屏以成交额为中心，展示沪深京 A 股合计与分交易所数据、过去 20/60 个交易日比较、涨跌家数、主要指数趋势。

第二屏展示一级行业成交额、占比及变化、行业成员覆盖率。默认用单一、明确版本的行业分类；历史成员数据未验证前，仅开放当前行业快照，不绘制伪历史行业曲线。图中点击一天可查看计算口径和数据批次。

“全球与宏观”在 V0.1 只展示已接入的官方宏观发布列表；全球行情面板在 V0.2 完成，不用空卡片占据首屏。

### 4.2 公司工作台

概览：主体名称、证券代码、所属行业及来源、关注状态。行情与状态：原始/复权口径、成交额、成交量、换手率、趋势与价格位置。

研究页：研究问题、主营业务、已识别收入结构、概念相关性、证据与未知项、资料列表、用户笔记。V0.1 采用“资料检索 + 可保存的证据卡片”，不承诺自动完整解析每家公司全部财务附注。

每条业务判断展示所属期间和证据等级。例如“存在技术储备”“已有产品”“披露客户验证”“披露订单”“披露收入”分开记录；订单额、收入额、客户名称各自需要证据。公司未单独披露收入占比时，不从概念标签、合同总额或分部合计倒推出占比。

“行业龙头/细分龙头”要求明确指标、范围、年份和比较依据；公司自述“领先”标注为公司自述，不升级成系统结论。

### 4.3 My Focus 与研究项目

证券可以同时具有“当前持有”“重点观察”等关注标签；研究项目另有 active/paused/completed 状态，因此“正在研究”不与“持有”互斥。已研究保留报告与资料。

新建研究项目建议默认获取最近 3 个完整年度年报、最新半年报、近 12 个月重要公告及 IR 记录；可调整年份与类别，下载前展示数量及预计体积。重点公司每日增量检查；暂停项目停止自动深度归档，但不删除既有资料。

### 4.4 证据与资料

统一证据侧栏：标题、发布方、发布时间、获取时间、报告期间、页码/段落、支持原文、本地原件与官方链接。扫描 PDF 未解析成功时可阅读原件，但不能伪造段落引用。

### 4.5 AI 研究入口

默认继承当前证券/行业和时间上下文。回答按“有证据的事实 → 计算与比较 → 推断 → 未知项”组织；事实与计算都有可点击来源。支持保存研究快照。AI 不可用时，前述页面和工具仍可使用。

### 4.6 数据管理

显示来源状态、权限错误、最近成功同步、缺口、待重试、版本覆盖、空间使用和备份状态。允许重试指定任务、导入有来源的本地文件、导出研究项目。所有数据问题可追溯到批次。

## 5. V0.1 范围契约

| 领域 | V0.1 必须交付 | 后续扩展 |
|---|---|---|
| 市场覆盖 | 沪深京普通 A 股日线与证券主数据；指数建议上证综指、深证成指、创业板指、沪深300、北证50 | 更多指数、风格与细分板块 |
| 初始历史 | 建议自 2015-01-01 起至最近完整交易日；不足上市年限从上市日开始；含期间退市证券，保存实际覆盖边界 | 可用的更早历史逐步回填，不删除已获取历史 |
| 基础指标 | OHLC、成交额/量、复权因子；每日换手率、股本、市值、PE/PB、股息率在来源支持范围接入并报告缺口 | 更丰富基本面与行业特有指标 |
| 行业 | 一套一级行业分类及当前成交分布；快照自开始采集之日积累 | 历史成员验证后再做长期行业比较；概念板块另建体系 |
| 状态 | 可解释的原始指标、移动均线、回撤/涨幅、历史分位；规则版本化、标记研究性 | 历史验证后的企稳/过热规则；不承诺预测 |
| 公告 | 全公司增量公告索引；建议初次回填近 12 个月；重点公司按项目归档 | 更早全市场索引及更多资料类型 |
| 公司研究 | 少数重点公司完整文档、关键词检索、带证据业务卡、基础报告 | 财务自动结构化、收入分部比较、产业链关系 |
| 官方信息 | 国家统计局、中国人民银行各至少一个稳定栏目增量归档；覆盖宏观发布与金融政策信息 | GDP/PMI/CPI/PPI/M1/M2/社融等历史结构化序列、更多监管和政策源 |
| AI | 一个可替换模型适配器、只读 Tool Layer、事实与计算证据、保存报告 | 更多研究工具与本地模型优化 |
| 时间正确性 | 从第一天记录版本与可知时间；历史不足明确拒绝/标注 | 扩展真实历史 vintage 数据 |
| 运行 | 本地核心引擎 + 桌面应用；默认先验收当前 macOS 平台 | Windows/Linux 打包验证 |

上述历史起点、项目回填范围和平台是建议默认值，不是用户已确认的新要求。来源采购未授权，先验证可访问性与现有凭证；若无法满足核心历史覆盖，提出明确的范围调整，不以演示数据宣布 V0.1 完成。

## 6. 估值与状态的表达

稳定/红利型 profile 预留股息率、分红连续性、ROE、PB、盈利稳定性及银行特有指标；成长型 profile 预留收入和利润增长、现金流、行业趋势、业务受益证据。V0.1 只实现 profile 注册机制与已获数据的展示，不套用同一模型评判所有行业。

研究性参数建议从 MA20/60/120、20/60 日涨跌幅、252 日高低位、成交额相对前 20 日均值起步。它们是描述统计参数，不是买卖阈值；不足窗口显示样本数，不能偷偷缩短窗口后仍标注原窗口。

价格低位、估值低位、趋势改善、基本面改善分别呈现。趋势仍向下时，即便历史估值较低，系统仍并列显示两者。过热页同样只展示异常程度与依据，不因创新高自动要求卖出。

## 7. 验收场景

| ID | 场景与通过条件 |
|---|---|
| A01 | 同一数据快照下，GUI、Python 和 Tool Layer 返回一致的市场成交额、口径与覆盖率。分交易所合计可复算；缺失股票不能默认为零。 |
| A02 | 样本公司大幅下跌但长期趋势向下：同时展示价格位置和下行状态；不出现 BUY、抄底机会、综合推荐分。 |
| A03 | 样本公司的概念只有技术储备证据：回答不能断言已有收入、主营占比或已签订单；证据原文可点击。 |
| A04 | 历史截止在某公告发布之前：搜索、公司画像、AI 提示上下文和引用均不包含该公告及其后续总结。 |
| A05 | 同期数据修订前后均被保存：旧报告仍能重放旧版本，最新查询展示新版本；无历史 vintage 时明确限制。 |
| A06 | 市场与资料完成一次同步后断网，仍能浏览本地数据和原件；模型连接失败不会阻断这些操作。 |
| A07 | 同步中强制退出并重启：断点续传，批次不重复计数，用户只看到完整已提交快照；资料失败可单独重试。 |
| A08 | 1 个稳定型、1 个成长型样例项目完成归档、查询、证据卡和每日更新链路。可以用合成材料做自动测试，但发布验收另需真实官方资料。 |
| A09 | 空间接近预算时能停止非必要下载并保留数据完整性，自动清理不删除被研究结论引用的原件。 |
| A10 | AI 输出的关键事实和数值在固定评估集中 100% 带可解析证据引用；人工检查至少 30 个代表问题，无无依据的关键事实。引用完整不等于语义正确，需双重检查。 |

性能目标用于验证，不是现有性能承诺：在实际目标机器记录配置；热缓存市场总览 p95 ≤ 2 秒、单股十年日线查询 p95 ≤ 2 秒、5 万文本块本地搜索 p95 ≤ 3 秒。冷启动、初次回填和 AI 网络耗时分别报告，不混入上述指标。

## 8. 明确排除

V0.1 不做分钟/Tick、高频、自动下单、券商接口、自动荐股、黑盒买卖预测、多 Agent、复杂 Portfolio、社交、登录、多用户、会员、支付、云 SaaS、手机应用、大规模机器学习选股。

未来交易导入与行为分析、完整事件研究、vectorbt/Qlib 仅保留边界，不建空实现。用户不必为了看行情或资料先配置 AI。

## 9. 确认范围

本提案建议确认：V0.1 的最小闭环、模块化单体与存储分工、历史范围默认值、以数据质量和证据可追溯作为发布门槛。具体供应商权限、行业分类可用性、扫描件处理和打包能力交由前置验证解决，不重新询问既定产品方向。
