## 1. 产品定义与成功标准

TheWolf 是面向个人中长线投资者的本地研究工作台：提供市场、行情、公司与资料看板，并围绕投资论点进行研究、决策记录、持续监控和复核。

核心痛点是投资过程高度依赖直觉和被动信息，难以解释、验证、复盘与改进。第一个真实数据切片验证数据获取、本地保存和离线读取路径；它不能证明扩大数据库就是产品价值，也没有验证投资论点流程的使用价值。

产品有两个相互连接的功能领域：

- **市场观察与资料支持**：日常查看价格、交易活跃度、估值、资金与信用环境，减少为了基础数据频繁切换其他软件。
- **投资论点及其演变**：保存当时为什么关注、依据是什么、为什么采取或不采取行动、何时重新考虑，以及后续判断如何变化。

投资论点是核心研究对象；市场总览是默认首页。市场、公司和论点页面可以分别使用，并能相互关联。不限于由 Thesis 临时触发全部数据，也不以股票或数据库替代研究对象。

成功标准包含两方面：能看懂市场状态、追溯资料和计算、识别缺口；能以可接受的录入成本保留决策理由和反证、按时复核、解释判断变化。收益和预测命中率不能单独证明过程质量；单次结果不能精确分离能力与运气。一年期效果的具体衡量方法仍待设计，不预设收益目标或使用率数值。

## 2. 产品原则

- 原始用户表达与 AI 结构化论点分开保存，AI 不覆盖原话；修订追加版本。后来回忆的理由标为回忆，不能冒充当时记录。
- 用户可以先快速记想法，再补理由、时间窗口、重新考虑条件与信心；允许未知。几分钟完成是体验目标，不把复杂对象模型变成大量必填字段。
- 行业判断、公司受益、市场定价与个人行动分别讨论；行业正确不等于公司正确，公司优秀不等于当前值得买，论点正确不保证盈利。
- 事实、计算、推断、预测、第三方观点和未知明确区分；AI 记忆和推断不作为独立外部证据，引用存在还需核查是否支持结论。
- 保留竞争解释、反证与冲突。十篇转引同一报告不算十条独立证据；证据来源性质、时效与依赖分别描述，不以单一可靠度分数替代判断。
- 价格位置、估值、交易活跃度、银行间资金成本与实体融资环境分开展示；不合成黑盒买卖评分。成交额不等于净流入，分位不等于上涨概率。
- 历史数据区分所属期间、发布时间、获取时间和修订版本；当前修订值不冒充当时可知资料。缺失、不适用、过期和未披露不能当作零。
- 本地已有数据、资料和确定性分析不依赖 AI 连接。离线可读已归档内容；新增联网数据和远程模型分析分别说明条件。
- 规则、个人状态和实际决定由用户拥有；AI 分析与用户最终决定分开记录，不提供自动交易或无依据荐股。

## 3. 关键用户流程

| 流程 | 用户动作与结果 | 边界 |
|---|---|---|
| 收盘后观察 | 从市场总览查看已完成交易日的指数、涨跌分布、成交额和指标；切换时间范围及组合图 | 数据各自显示实际日期，不用统一“今日”掩盖跨市场时差和发布滞后 |
| 公司研究 | 打开自选、持仓或用户定义的龙头，查看行情、资料和相关论点 | 龙头由用户定义；系统分析仍需说明范围和依据 |
| 记录想法 | 保存用户原话，逐步补充理由、时间窗口、重新考虑条件、信心 | 不要求先查齐资料；AI 提出少量遗漏问题，用户可确认或忽略 |
| 形成论点 | 围绕行业、公司、估值拆子问题，关联证据、反证、竞争解释与未知 | 最低正式登记标准、状态转换仍待论点阶段细化 |
| 作出决定 | 保存买入、卖出、继续持有、不买或继续研究等决定及当时上下文 | AI 分析不能自动变成用户决定；不操作也值得记录 |
| 持续复核 | 按复核日期或手工触发检查论点变化，记录维持、修改或放弃理由 | 早期先做日期/手工复核；自动监控按变量可观测性扩展 |
| 历史回看 | 查看固定决策时点的原话、论点、证据、个人状态与规则版本 | 数据快照不等于决策快照；旧决定不随最新数据重新改写 |

研究生命周期可以在想法、论点、研究、决策、监控、再评估和复核之间循环，并不要求每条想法都买入。已有持仓再评估优先作为论点 Demo 候选，具体案例不预先指定；完整交易导入和盈亏归因后置。

## 4. 信息架构与页面

### 4.1 市场总览

默认首页展示主要指数、A 股集中涨跌概况、成交活跃度及可进入的指标看板。导航可切换想法、待研究问题、待复核论点、个股、自选和资料。功能入口不表示相应能力已经实现；具体布局、视觉和空/错/离线状态在开发前确认。

A 股涨跌区域参考用户提出的同花顺手机版集中展示思路，尚未确认具体视觉稿。指数、公司页面与 Thesis-driven View 同时存在；论点视图突出与该论点相关的变量，市场总览不要求绑定论点。

### 4.2 公司工作台

展示主体与证券身份、关注状态、行情、适用的估值、资料及相关论点。公司、证券、行业与市场概念分开；公司业务判断回到正式披露，技术储备、产品、验证、订单和收入不能相互替代。

行业分类、自动财务结构化、同行比较等按研究需要扩展，不作为第一批所有看板的统一前提。不同类型公司的估值方法不强行统一，亏损等不适用情况明确显示。

### 4.3 My Focus 与研究项目

自选、持有、重点观察、正在研究可以重叠。个股长期数据面向用户自选、用户定义的主要行业龙头及实际研究需要；不默认保存全部 5000 多只个股的完整长期历史。

取消自选或暂停研究不删除已有历史、原件、笔记与决定；后续更新是否继续，应检查其他仍有效的持仓、研究或监控需求。具体更新触发规则待设计。新研究不默认无条件回填大量公告；所需材料、时间范围、数量与体积按研究需求说明。

### 4.4 证据与资料

证据保留原内容、来源、发布时间、所述期间、获取时间、版本、原件定位及适用性。分别描述事实/预测/第三方观点、来源依赖、支持或反对的子问题、冲突与过期情况。

外部原件和可复算的确定性计算可作为证据；AI 分析必须指向它们，不能由另一轮 AI 改写后重新当成独立支持。保存报告或决定时固定相关输入，外链后续失效不能破坏已归档证据。

### 4.5 AI 研究入口

早期辅助结构化用户表达、提出少量关键问题、分析指定资料及整理证据，不要求大规模自主联网研究。联网上下文、模型选择和费用限额在对应阶段明确；远程服务发送个人状态或资料前明确范围，默认只使用必要内容。

AI 输出与用户确认的论点、决定分开保存。没有模型连接仍可记录、查看资料和使用确定性指标。

### 4.6 数据管理

显示各序列来源、实际数据日期、覆盖、最近成功更新、缺口、版本局限和空间使用。支持时间筛选；历史存得长不要求一次全部渲染。日线/月度指标按各自频率更新，月度数据不插值伪装每日新观测。

### 4.7 论点、个人规则与决策复核

概念对象包括 Thesis、Sub-question、Hypothesis、Evidence、Decision、Strategy/Policy、State Snapshot、Monitoring Variable 和 Review；是领域方向，不是本轮数据库建表清单。行业论点可关联多家公司，一次决定可依据多条论点，一个证据可关联多个判断。

Strategy/Policy 记录变化较慢的个人规则，旧版本不可覆盖，变更记原因；State Snapshot 保存决策当时相关资金、持仓、暴露、现金和流动性需求。早期允许手工录入必要快照，不要求完整账户账本，不预设仓位或风险上限。

Decision Snapshot 固定原话、论点版本、信心、支持与反对证据、未知、数据输入、规则与状态、备选方案及不操作选项、参考基线、AI 分析、用户决定与下次复核时间。完整字段按阶段细化，不将上述每项都变成用户必填。

Review 对照当时记录检查哪些子判断成立、被削弱或尚无证据，以及遗漏与后续改进。监控变量分自动可获取、人工补充、不可观测；不能假设 AI 能取得全部重要变量。

### 5.2 第一批指标

以下七组建议已获用户认可。参数作为首批默认显示口径；正式公式、异常值、样本量与来源映射在实现前固定版本，不赋予买卖阈值含义。

| 组别 | 指标与默认观察口径 | 解释边界 |
|---|---|---|
| 价格位置 | 收盘价/点位、20/60/250个交易日涨跌幅、五年走势、距离窗口最高收盘价的跌幅 | 价格位置不等于估值；个股长期比较须说明复权，指数区分价格/全收益序列 |
| 涨跌分布 | 上涨/下跌/平盘家数、收盘涨停/跌停家数、上涨占比 | 上涨占比分母为可有效判断涨跌的当日交易证券；说明排除和缺数；涨跌停不是独立可相加的第五类证券 |
| 交易活跃度 | 当日成交额 / 前20个交易日日均成交额，同时显示原金额；均值不含当日 | A股与港股分别展示，范围/币种一致；成交额不是净流入，也不能单独代表交易冲击成本 |
| 指数估值 | 滚动市盈率 PE-TTM、市净率 PB及各自五年历史分位 | 优先比较同一指数自身历史；注明权重、股本与亏损处理方法及版本；不足五年不伪称五年分位 |
| 股债比较 | 盈利收益率与中国10年期国债利差、股息率与国债利差；可切换股息率/国债收益率倍数 | 盈利收益率不是承诺回报，分红可变；先适用于 A 股宽基，港股不能直接套用人民币债券基准 |
| 短期资金成本 | DR007 与央行7天期逆回购利率同图；香港单列一个月期港元 HIBOR | DR日终加权利率不与 FDR 定盘利率混用；低资金成本不等于股票获得资金流入 |
| 货币与融资增长 | 社融存量同比、M2同比同图；辅助展示前者减后者的百分点差 | 不用当月新增社融同比替换存量同比；差值不代表准备流入股市的资金量 |

图表允许按问题搭配；原始两条序列可见，差值/比值不算额外独立证据。每个指标应有“是什么、为什么看、能说明什么、不能说明什么”的解释入口。五年分位显示实际期间、有效样本和定义，不解释为上涨概率。

### 5.3 历史、频率与保留

- 收盘后使用、日线级别；当天市场已结束且来源通过完整性校验后可纳入，不能仅按钟点假设数据齐全。各市场、商品及海外利率分别标实际日期和时区。
- 所选日线历史最终目标至少五年；公共序列尽可能覆盖同一长期观察窗口。新上市/新设序列不足时显示实际起点，指数回溯与发布后历史分开。五年价格不代表五年估值或当时可知证据也齐全。 **阶段约定（2026-10-05用户确认）**：五年是最终目标，不是前期开发的前置条件；初期按对应切片所需的较短窗口开发和验收。首个沪深300价格切片以已验证的260个交易日为依据，五年回填、连续覆盖和长期指标留在后续对应步骤完成。
- **首版日期边界（2026-10-05用户确认）**：沪深300M01先更新到上海日期之前的最近交易日；当日日线的完成判据以后验证。该阶段约定不取消上方未来可纳入已完成当日日线的目标。首版具体设计见[看板设计§5.6](Market-Dashboard-Design-V0.1.md#56-沪深300首版p02实施设计2026-10-05)。
- 默认不滚动删除已保存历史；取消自选不删除历史。容量问题先实测，再讨论范围/存储调整；150 GB软上限不授权自动丢弃历史或研究依据。
- 长期基础参考数据与历史决策证据分别管理；后者包括当时网页、公告、预测、原始发布值、固定输入、用户表达和决定。
- 来源保持免费且准确优先，合理免费路径不足再讨论替代；本节不授权采集、付费、定时任务或数据库迁移。

| 历史与保留 | 可筛选已保存历史；取消自选后仍可读；五年不足如实标识 | 隔离数据与界面验证 |
| 时间与证据 | 新修订不改变旧固定依据，无历史版本不冒充当时可知 | 版本/未来数据反例、原件定位与恢复 |
| 离线与失败 | 无模型连接和断网时已存资料可读，更新失败保持上一有效版本 | 隔离断网/失败/中断恢复 |
| 论点录入 | 原话与AI结构化内容可区分，修订可追溯，用户实际可接受录入成本 | 真实案例交互试用、用户确认 |
| 决策与复核 | 找回当时理由/反证/未知/规则/状态，记录不操作与后续变化 | 一个真实论点跨至少一次决策和一次复核的流程验证 |

看板交付不能被记为论点闭环验收；交互演示不能被记为长期保存和真实定时复核已经验证。具体成功率、用时、样本量和一年后评价尺度仍待实际使用设计，不自动沿用旧提案性能数值。

## 已确认的测试隔离与日常更新行为 · 2026-10-03

用户确认：测试通过后更新程序，保留日常正式库原有业务数据；测试库的数据更新结果不得自动带入正式库。这里的“正式”指用户日常使用的本地数据根，不要求云端生产环境。

- 测试窗口点击“更新日线”只改变指定的隔离测试库，不更新、覆盖或替换正式库，也不把测试任务状态、成功检查时间或故障配置带入日常环境。
- 更新程序后，正常启动仍读取同一个正式库，展示其原有行情截止日、公告与历史快照；启动本身不触发行情采集，不自动导入测试快照。

- 正式更新成功后展示新的有效窗口；无变化如实提示；失败保持原数据及最近成功检查时间，旧快照和公告保留。
- 若新程序要求调整数据库内部结构，应单独识别、验证并按授权执行必要升级，保留原业务数据和历史依据；不能把“更新程序”理解成永远不发生内部结构变化，也不能借升级把测试数据替换进正式库。未就绪时明确说明原因，禁用状态不得伪装成正在更新。
