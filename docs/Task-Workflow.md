# 任务分级与交接流程

2026-10-23规则有效；2026-10-24整理模板与入口。授权和操作红线见[AGENTS](../AGENTS.md)，审查检查与通过条件见[独审规范](Independent-Code-Review-Policy.md)，实际命令见[README](../README.md#验证入口)。旧原文（仅在本地保全历史中）及未生效候选（仅在本地保全历史中）仅供追溯。

## 1. 任务大小分级

小、中、大任务的判据、拿不准时的处理及审查方式统一见[AGENTS任务分级](../AGENTS.md#任务分级)，本节不另维护判据。范围扩大时重新判断受影响部分，不重做无关工作。

| 大小 | 交接做法 |
|---|---|
| 小 | 采用下方短任务书；自检后登记技术完成，无需独审、独立报告或固定快照包。 |
| 中 | 采用下方短任务书，完成受影响验证及适用独审。 |
| 大 | 本人决定关键取舍，固定本轮方案，按适用分级完成代码审查及必要恢复验证；方案独审按[AGENTS](../AGENTS.md#任务分级)规定的触发条件执行；不提前设计整个产品。 |

流程：核对授权范围与预定标准→实施→验证、适用独审及恢复→登记技术完成并汇报；不扩大授权。界面查真实页面，构建不代替使用验证；用户验收适用范围按[AGENTS](../AGENTS.md#任务分级)，不把技术步骤逐项交回签字，退回按第4节处理。

接力不自动升级任务：小任务可在汇报中交接，不因换模型补全套文档。中、大任务使用下方模板，可合并写入已有记录。复杂任务仅按真实依赖或独立交付价值拆分；内部步骤、开发与独审往返沿用原任务，不递归拆管理子任务。参与者和是否自动传递沿用本人安排，工具不支持时交回相同材料供人工传递，不虚构已发送。

## 2. 一页任务书模板

任务书沿用已有ID及材料，五项可合写，新文件放`docs/tasks/`；不自行产生授权，已有定义引用不重抄。开工与标准变更按[AGENTS](../AGENTS.md#任务分级)。

```text
目标：解决什么问题，带来什么可观察变化。
范围：本轮做什么、不做什么；关联需求/计划及实际子范围（如有）。
做到什么算完成：写明前提、操作、可见结果及核对方法，注明指令依据或必要认可。
必要约束：必须保持的行为及依据；任务大小、风险理由和适用审查。
状态入口：status或归档定位，含授权、技术完成、用户验收适用性及状态、下一步和证据。
```

按实际需要补充，不要求逐项建栏目：

- 涉及代码或既有工作：相关源码/设计、基线与已有改动、影响文件/调用者/接口、兼容边界。
- 涉及运行验证：必要环境与隔离输入、正常/异常/恢复场景、恢复方式及未覆盖项；不复制整套命令。
- 需要交接：执行/审查及唯一写入者、交接渠道、版本取得方式与既有Git策略，直接引用已确定安排。
- 有依赖或未知：只列影响本轮的条件、解除方式和所需决定；延期事项单列并注明恢复条件，不默认成为前置。

任务书及必要引用须支持开发、交审和用户验收；关键要求须落盘，已有授权及安排不因补模板重问。旧约定保留原时点，旧模板、章节及计数不覆盖现行规则；冲突按第4节处理。

中、大任务的方案及代码应能对应实际版本：使用真实提交，或真实基线加必要差异和文件清单；包括依赖的未提交/未跟踪内容及必要文件模式。固定后核对测试与审查对象一致，不能只交变化中的工作区、虚构提交号或用摘要冒充提交。只有确有独立重建需要时才制作固定包，不复制无关历史、真实库或凭据。

## 3. 一页交接模板

开发、审查、修复共用下表；在已有记录写一次，任务书和status引用，小任务可直接回复。不预建空报告，不覆盖历史结论。每个可用阶段提供2—3个可与常用交易软件对照的实际数字及简短步骤，注明对象、日期、单位、口径与预先认可的允许差异；缺数或不可比须明示，不编造、不用模拟数替代。

```text
交付范围与状态：日期、阶段、技术完成、用户验收适用性及状态、范围边界。
版本与差异：所测/所审对象、比较基线、相关未提交材料；实际改动。
验证：实际命令、工作目录、必要环境和隔离输入、结果；哪些没验证。
审查：实际审查者及独立性、检查范围、结论；不需要独审时注明依据。
问题：ID、位置、依据、预期与实际、证据、影响、是否阻断及关闭条件。
恢复：测试前相关状态、临时影响、实际恢复核验；未恢复项及影响。
修复：审查修复轮数（最多2轮）；用户验收退回按AGENTS区分；本轮处理及剩余问题。
接手：必要材料位置、下一步；需要本人决定的具体事项。
```

接手者自行定位已有材料，核对范围、版本和必要证据；只有无法唯一判断时才澄清。缺关键材料就说明具体阻塞及解除条件，已有有效证据保留；阻塞不冒充完成。补充材料、报告和Git版本分别说明，报告不必包含自己的摘要或提交号。

指定维护者更新[status](status.md)，任务书引用；授权记内容、范围、日期。技术结项按AGENTS归档，用户验收另记；历史“待审”不代表当前状态。Git及发布依各自授权，不为填版本重复提交。

## 4. 审查修复的停止条件

审查修复最多两轮，不含用户验收退回及对应修复。首次交付后，每次集中修复或补证、验证并重新交回记一轮，与是否已经进入正式审查无关；内部编辑和测试次数不另计轮次，原材料重传不重复计轮。第2轮后仍有阻断或还需修复，停止，交本人决定，不自行开始第3轮、不自动判通过、不新增任务。

用户验收退回后的原因说明、修复、重新验收和连续退回停止条件，统一按[AGENTS任务分级](../AGENTS.md#任务分级)执行；不重置审查修复轮数。

同一任务不因换模型、会话、交接渠道或阶段而重置轮数。旧任务的历史记录与结论不重算，已停止任务也不因此自动获准继续。此条替代原三轮共享计数、同根因失败次数及其组合阈值，不同时运行两套计数。

遇到关键约定冲突、需要改变重大范围或数据策略、缺必要权限/材料/环境时，停止依赖它的动作；已有授权内不依赖该问题的工作可继续。停止时交回剩余问题、实际证据、已尝试方法、可选处置及所需决定，不擅自回滚、删除数据或降低验收条件。

## 5. 文档写作与预算

单文件汉字上限统一见[AGENTS](../AGENTS.md#细则入口)。默认必读集合仍为README入口指定的五部分，合计完整字符数上限为**15000**，常态参考目标为**10000以内**；目标不是硬上限，不要求压缩当前正文。此预算替代原“默认必读总量不增”，允许预算内必要更新；预算是阅读管理指标，不是模型上下文或token容量。

计量统一为UTF-8文本、换行规范为LF；完整字符数按Unicode码点计，包含英文、链接、标点、空白、换行、代码及Markdown标记，汉字按`U+4E00–U+9FFF`计。全文计至文件末尾；README最小入口从其二级标题起至“验证入口”二级标题前，包含按任务补读表；README验证入口计至下一二级标题前；PRD从§1标题起至§4标题前。默认集合各段直接相加，每段计一次，不扣除重复文字；不能通过改标题、拆文件或把内容移入另一必读文件规避预算。

任一单文件上限或总预算使用率**达到80%即预警**：总量为12000字符，AGENTS为1600汉字，status为2400汉字；其余按各自上限计算。预警提示关注增长并汇报，不等于超限，不单独阻断已授权工作或增加审批。超过上限须处理、复核后交付；必要边界无法完整保留时，明示超限及所需取舍，不能自行提高上限、截断内容或冒称检查通过。预警本身不授权压缩、拆分或删除现有内容。

写作与信息归属沿用AGENTS：新增内容先区分长期规则、当前授权/状态、需求设计与历史记录。同一要求只有一个完整定义，其他位置可简短提醒并链接；规则写清适用条件、动作、必要例外或停止条件，背景与案例按需读取。后续修改优先更新对应条目，避免反复追加重复解释；缺陷先修复验证，有共通缺口才建议修改规则。可复用命令以README为准，交付记录仍保留当次实际命令及结果。

status更新与归档继续按[现行维护规则](../AGENTS.md#status维护规则)，保留进度表和问题分组，不自动拆分；未关闭问题不能按已关闭事项归档，授权、数据安全及影响本轮判断的限制须可见。常规归档保留当次被替换原文及日期、结论、定位，不重复复制未变内容；确需完整版本恢复时保存全文，已有历史不改写。

按任务补读的规则、源码和证据须按实际需要读取，不能为预算省略必要检查；固定集合外的历史按具体定位读取。检查入口见[README](../README.md#验证入口)，分别报告单文件计量、默认必读总量、相对本轮修改前的增减及预警/超限，不另维护一套数值。
