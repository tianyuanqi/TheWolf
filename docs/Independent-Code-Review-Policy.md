# 独立代码审查规范

2026-10-23有效版。任务分级、交接及最多两轮修复统一见[流程](Task-Workflow.md)；授权与数据保护见[AGENTS](../AGENTS.md)。旧原文（仅在本地保全历史中）及未生效候选（仅在本地保全历史中）仅供追溯，不参与现行通过判断。

## 1. 何时需要独审

独审是由未参与本轮实现者检查代码；不是多开一个窗口或换一个型号就自动成立。

| 深度 | 适用情况 | 最低检查 |
|---|---|---|
| L0 自检 | 流程定义的小任务及纯文档整理 | 差异自检、相关工具或行为检查，汇报实际运行、结果及未验证项；无需独审。 |
| L1 常规独审 | 中任务中的普通功能和行为变化 | 检查本轮代码、测试、配置差异及相关调用者，核对适用验证。 |
| L2 重点独审 | 中任务中的核心金融、时间版本、来源适配、公共接口、发布与恢复 | L1加关键反例、失败恢复、兼容性及实际调用者/接口证据。 |
| L3 重大变更 | 流程定义的大任务 | 审查代码及受影响行为，必要时验证迁移恢复；方案是否须提前独审按[AGENTS任务分级](../AGENTS.md#任务分级)条款执行。 |

按实际影响选适用深度，不按文件数、改动行数或“重构”名称定级。测试、配置或依赖变更若改变关键行为或验证门槛，同样按影响判断。审查者核对定级是否符合实际范围；低估时说明所缺检查，不自行扩大产品范围。缺少必要方案审查不能倒写为已在实施前通过。

## 2. 独立性和材料

- 审查者未参与所审代码实现；方案审查者未制定所审核心方案。使用独立上下文，从需求、差异及调用关系建立判断，不复制完整开发历史冒充独立。相同厂商或模型可以审查，实际方式如实记录。
- 开发者摘要只是线索。审查者可提发现、关闭条件和建议，但若直接修改实现或制定核心方案，由另一位独立审查者检查其参与部分。
- 先核对任务约定、所审版本及必要差异、验证和恢复证据；方案阶段不要求尚未产生的代码或测试。代码检查以固定对象为准，不混入后续工作区修改；材料不足说明缺口，不能假定通过。
- 默认不修改原业务代码或有效测试；必要运行在隔离环境进行，并恢复自有临时影响。跨会话安排及Git权限沿用已有授权。

## 3. 实质检查

仅检查本轮适用项，相关证据仍有效时可复用，不无理由重跑全量。源码、测试和配置均须检查，机械生成物核对来源与一致性，不把AI代码当作免审生成物。

| 方面 | 检查要点 |
|---|---|
| 范围与正确性 | 实现符合约定；正常、空值、异常及边界结果有独立可判断的预期；无夹带功能。 |
| 接口与调用者 | 输入、输出、错误和运行时校验一致；公共修改检查实际调用者，双方模拟测试不代替实际联调。 |
| 状态与安全 | 重复、并发、迟到响应、取消、重试和中断正确；本地服务执行权限及路径/网络边界，不泄露秘密或误用真实数据。 |
| 数据与架构 | 遵守[业务约束](Business-Constraints.md)、已确认架构和契约；验证来源、单位、历史版本、发布、旧引用及恢复；只覆盖本轮能力。 |
| 界面 | 实际检查受影响页面及公共组件，覆盖适用的加载、空、错误、成功、窄窗口、键盘和焦点；构建不代替使用验证。 |
| 维护与证据 | 职责、类型、异常及说明符合[编码规范](Coding-Standards.md)；断言有效，结果对应版本、输入、命令和环境，恢复有核验。 |

## 4. 发现与通过

每项发现简记ID、位置、约定依据、触发条件、预期与实际、证据、影响及可判断的关闭条件；写明是否阻断。能由代码路径证明的问题不强求运行复现，疑点先查证，不把猜测或个人偏好直接变成修复。

- 阻断：违反已确认功能要求、安全或金融数据红线的真实缺陷；关键验收证据缺失；影响正常使用、数据安全或证据可信度的测试遗留。
- 非阻断：不影响上述要求的纯风格偏差、改进建议和范围外事项；记录即可，不自动扩大工作。问题严重程度按实际影响说明，不能以轻微为由放过真实业务缺陷。
- 修复核对根因、原关闭条件、新增差异及受影响路径；不删有效测试、不降低断言来通过。已关闭且未受影响的事项不反复重开。

正式结论为“通过”“需要修改”或“关键材料不足无法判断”，注明所审阶段、版本、范围及未覆盖项。通过须无未关闭阻断，必要验证及恢复证据充分，最终内容与所审对象一致。本人决定风险接受或调整范围时保留原未满足事实，不能改写为已修复。

修复最多两轮，停止不等于通过。独审仅支持技术完成，用户验收与操作授权另计。保留历史发现和结论；交接沿用流程模板，不另造审查任务或重复状态表。
