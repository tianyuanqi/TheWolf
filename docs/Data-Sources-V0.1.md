## 1. 来源优先级

用户已明确：优先选择免费且准确的数据来源；合理免费路径不能满足要求时，才讨论替代方案。日线最低历史要求见 [PRD §5](PRD-V0.1.md#5-v01-范围契约)。本策略不扩大已授权切片的采集范围。

选择顺序为：先判断字段、时间、覆盖、准确性和使用条件是否合格，再在合格免费来源中选择维护成本与稳定性较好的来源。官方公开数据优先用于事实证据和核验；批量行情可经免费数据服务或接口库取得。免费不能降低质量门槛，收费也不代表准确。

在已授权任务内，执行者可限量验证并采用符合本策略的免费来源，记录理由及契约，无需逐个候选再次请求用户选源。无账号候选先验证；免费账号接口在具备合法凭据时验证，不把缺少某一家 Token 当成全部免费路线阻塞。不得自动购买积分、开通付费服务或接受试用到期自动收费。

事实来源优先级保留政府/监管、交易所、公司正式披露/IR、一手研究与可追溯第三方资料的区分，并按具体事实判断支持关系；机构身份不能替代内容核验。第一阶段不建设新闻和社交数据流，但真实研究所使用的具体文章可以按历史证据归档，保留其观点性质与来源依赖。

数据传输方式不等同于事实权威性：日线批量获取可使用数据供应商，官方统计作口径核验；公司业务判断回到正式披露。每条记录同时保存原始发布方与传输渠道，不能因为通过某 SDK 取得就丢掉底层来源。

## 3. 已核验且影响设计的事实

1. Tushare 日线文档区分原始行情与复权，停牌期间不提供日线记录；成交量和成交额使用供应商定义单位。因此必须做单位转换、停牌识别和完整性检查，不能照搬字段名。参见[日线接口](https://tushare.pro/document/1?doc_id=27)。
2. 每日指标有账号权限要求，并区分普通流通与自由流通换手率、不同 PE 与股息率定义；本提案不锁定积分价格或承诺账号可用。参见[每日指标接口](https://tushare.pro/document/2?doc_id=32)。
3. 复权锚点与供应商计算方法会影响输出，必须保存方法和版本，不跨源混算。参见[Tushare 复权说明](https://tushare.pro/document/2?doc_id=146)。
4. 官方发布文章与统计数据库更新时间可以不同，所以不能把数据库更新时刻或统计期末当成首次公开时刻。国家统计局的日程说明给出不同更新安排，支持将“发布资料采集”和“结构化库同步”分开。参见[2026 发布日程说明](https://www.stats.gov.cn/xw/tjxw/tzgg/202512/t20251224_1962137.html)。
5. FRED 默认的 real-time period 与历史 vintage 不是同一概念；要恢复历史可知数据需显式选择时间范围。ALFRED 的日期精度也不能直接证明盘中何时可知。参见[FRED 时间语义](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)、[ALFRED 帮助](https://alfred.stlouisfed.org/help)。
6. AKShare 提供数据接口封装，其存在不证明所有底层接口稳定、允许批量使用或含原始历史版本。采用前逐接口检查来源及条款。参见[AKShare 官方文档](https://akshare.akfamily.xyz/)。
7. 2026-09-24 补查：[AKShare 股票文档](https://akshare.akfamily.xyz/data/stock/stock.html)展示 `stock_zh_a_hist` 的 2017—2024 年样例，含 OHLC、量、额、换手等；[指数文档](https://akshare.akfamily.xyz/data/index/index.html)说明新浪接口返回可得历史，东财指数接口标注近期数据。单个样例或 start_date 参数均不能证明所有证券/指数满足五年。
8. [Tushare 权限频次表](https://tushare.pro/document/1?doc_id=290)于补查时将 120 积分非复权日线档列为 0 元；[接口权限表](https://tushare.pro/document/1?doc_id=108)将 `daily` 与指数、每日指标等权限分开。仅将具备免费权限的具体接口列为免费候选，不把整个 Pro 产品视为免费；执行时复核实际账号权限。
9. [BaoStock 官方发布包说明](https://pypi.org/project/baostock/)声明免费股票数据并展示日线接口。本次官网未读到完整历史覆盖说明，故五年、北交所及退市覆盖仍是待验证项，不宣称已经满足。

10. 2026-10-04 讨论中核对：[AKShare指数估值接口](https://github.com/akfamily/akshare/blob/main/docs/data/index/index.md)注明中证该接口仅返回近期数据，且存在总股本/计算用股本口径。五年估值不能由五年价格或该接口存在推定；同一官方首页有指标也不能推定历史接口完整。
11. [央行M2说明](https://www.pbc.gov.cn/rmyh/109339/2025080818580470423/index.html)与[社融存量统计定义](https://www.pbc.gov.cn/diaochatongjisi/attachDir/2025/11/2025110511314347909.pdf)支持区分货币量与实体融资余额。统计口径调整/可比增速需保留版本，二者增速差不能当作股市净流入。
12. 同一上游经多个平台转录不是多条独立证据；基准价/收盘价/结算价、实际发布/回溯历史也不能仅凭名称相近而合并。上述产品文档核对不包含数据批量采集验证。

## 4. Fallback 的实际执行规则

每个数据集维护 `source_policy_version`，将权威性、字段语义、覆盖、历史版本能力、延迟、费用/权限分别记录，不用单一总分自动决定来源。

1. 首选源失败先有限重试；旧完整快照仍可用但标注 stale。
2. 备选源只有通过字段单位、证券映射、交易口径、复权方法、历史期间对照后才能发布。无合格备选则保持缺口，不从页面随意抓一个数补上。
3. 切源使用新批次、新 source_id、新 policy_version，保留原始版本。整日/字段组按一致口径切换，不从多个来源拼一个看似一致的 OHLC 或复权序列。
4. 差异超出预先验证的容差进入隔离；股价精度、金额舍入等容差分字段定义。更权威来源也不能覆盖掉不同交易范围的值。
5. 文档镜像只有内容哈希或可靠官方标识能确认同份时才合并；否则分别留存，标注可能重复。更正公告关联原公告而不是覆盖删除。
6. 模型永远不是 fallback 数据源；人工导入必须附来源、时间和单位，未验证文件标为 user_supplied，不自动晋升官方。
7. 首个免费候选失败不直接转付费。先区分环境网络、临时限流、字段缺失、历史不足与来源质量问题，在允许范围有限重试并验证有依据的其他免费候选。不得绕过限制，也不无限尝试。
8. 合理免费候选仍不能满足要求时，向用户提交具体缺失字段/市场/日期、已试来源与失败证据、对页面/分析的影响，以及其他免费组合、带来源人工导入、范围调整或收费方案的能力/费用比较。付费、缩减核心范围或改变重要口径均待用户决定；未经决定保留缺口与旧完整快照。

### 准确性与五年覆盖验收

- 在已授权范围内固定证券、截止日与来源版本，保存原响应/请求参数、获取时刻、最早最晚日期及行数。完整五年能力验证需覆盖整段日历，不以窗口两端有数据代替中间连续性；当前 60 日切片不因该要求自动扩大回填。
- 按交易日历逐日检查，结合上市退市/停牌证据区分合法无记录和未知缺口；新上市证券从上市日开始。指数正式发布与回溯历史分开。分市场、字段、证券列覆盖结果，不能用少数样本推定全市场完整。
- 核验 OHLC、非负量额、重复键、单位转换、证券身份和交易范围；选择普通日、除权日及适用的停复牌/代码变更边界，与官方可得资料及另一可追溯来源对照。两个封装同一上游的接口不算独立核验。
- 容差依据源精度、单位换算与舍入规则预先定义；不一致逐项解释，未解释关键差异不准入。市场汇总按 R02 对账，不能以个股检查替代。
- 对复权保存方法、锚点和因子版本；对财务/估值检查当时可知性。只得到最新历史修订值时标为 latest_only，不声称拥有严格 PIT 历史。
- 在不同取样时点复查更新与更正行为，记录请求限制、超时、重试及断点恢复能力。质量通过范围仅限实际已核验字段、市场和期间；免费与收费均执行同一准入要求。

- 期货连续规则、原合约、换月与调整是否可追溯，收盘/结算字段是否混用。

- 市场汇总的范围、缺失、涨跌停规则与原始发布是否足以支持其展示，是否具备宣称的逐股复算能力。

### 8.3 日期、日历和代表样本

1. 执行开始记录带时区时间 `T`（Asia/Shanghai），冻结一次取样截止日 `E`。先由两交易所官方日历确定最近已完成交易日；若当天交易已结束且来源完整性有依据才纳入。依据不足时明确排除当天；若预期已完整的较早交易日缺数据，不继续向前挪截止日隐藏缺口。跨午夜恢复仍沿用原清单的T/E，不自动变成新一轮任务。
2. **近期W260**：从E按核实日历倒推260个交易日，起点为这260日的首日；生成全部预期日期并逐日对账，不把“来源最后260行”当完整窗口。相邻收盘用于20/60/250日输入检查，首日无前一日价格时昨收标未知，不额外扩窗凑值。本轮不交付这些指标页面。
3. **五年前H5**：E所在年月向前五年的整个自然月；**中间年份HM**：E所在年月向前三年的整个自然月。只抽取其中预期交易日，代表窗口固定后不因缺失更换月份。如果E落在2026年10月，候选窗口分别为2021-10-01—10-31、2023-10-01—10-31；这些是日期范围，不表示每一天开市。实际执行延期则按E规则重算并在首次请求前固定。
4. 本次规划日期为2026-10-05。按仓库已有2026年休市记录，近期截止日候选为2026-09-30，**尚未核验来源完整性**；若E最终为9月30日，历史窗口相应为2021-09-01—09-30及2023-09-01—09-30。W260起点须先补2025年日历才可给出，不能凭周一至周五推算。日历依据至少覆盖W260及H5/HM所涉年份，后续执行不得沿用本例日期冒充实际截止日。

### 8.4 总请求预算、重试与文件上限

下列数值是本方案为首轮设计的执行上限，待执行指令采用后生效，不是已经发生的请求数或性能承诺。

- 每个逻辑请求最多首次1次加重试10次，24 × 11 = **264次网络尝试上限**。为使实际出站有上界，重定向每一跳也计入全局264次；每次尝试最多跟随3跳，检查目标仍为预登记的合法来源。不额外发送HEAD“试探”；如确需发送也纳入清单与额度。总预算先耗尽即停止，不保证每个请求都用足10次重试。
- 串行执行、并发1，同主机两次出站至少间隔5秒。对连接/读取超时、临时5xx和可重试429，十次等待基准依次为5、10、20、40、80、160、300、300、300、300秒；来源要求或有效 `Retry-After` 更长时按更长值。需要较长等待时可中断保存、以后恢复，不重置次数，不设置后台自动化。
- 成功即停止重试。401/403、验证码、明确禁止访问、确定404或语义错误不连续重试；停止相应请求，记录原因。合法空数据、字段缺失、身份错配、解析与对账失败不是网络重试理由；先离线诊断。第10次重试仍失败，停止该请求及依赖步骤，独立来源/辅线可在原预算内继续。
- 每次连接超时5秒、读取空闲超时15秒、含重定向的尝试硬截止45秒；这须由受控探针实际保证，普通SDK的timeout参数不等于总时限。下载和解压流都受单响应 **8 MiB** 限制；所有尝试累计接收正文最多 **64 MiB**（失败、截断、重复、重定向正文均计入；有压缩时同时计量传输/解压后字节，各自不得超限）。Content-Length不可信，流式计数，超限立即停止。
- 测试根全部原件、派生表、日志与报告最多 **128 MiB、128个文件**；按尝试逐条写同一JSONL账本，失败正文仅保留最多4 KiB摘要，不逐次堆满文件。成功原件按哈希去重，保留每次获取时刻；流式下载前检查剩余预算，部分文件也计入上限。触顶保留证据并停止，不自动删旧证据腾空间或静默只留最后260行原件。
- `request-ledger.jsonl`在每次出站前追加请求ID、尝试序号、时间与剩余预算；结束后追加状态/错误类别、字节数、最终URL、耗时及对象哈希，不存凭据。出站前预留本次最大正文预算，完成后按实际字节结算；中断留下未完成尝试也占一次，字节数无法可靠恢复时按已预留上限计入，不低估累计流量。再次运行从账本累计，不因改进程/会话而重置。缺失/损坏账本时停止恢复，不能从零再跑。将所有隐藏SDK调用、分页和重定向纳入同一计数；做不到就不启用该封装。

## 10. 新浪沪深300精度离线复核（2026-10-06）
