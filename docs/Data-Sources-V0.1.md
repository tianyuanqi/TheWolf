# Data Sources & Validation V0.1

核验日期：2026-09-18。本轮只核对官方公开文档和页面；**没有实测个人账户权限、接口稳定性、完整历史覆盖或批量抓取能力**。下面区分“文档已核验”和“待小样验证”，不把候选来源当成已经接通。

## 1. 来源优先级

事实权威性顺序沿用用户要求：政府/监管 → 交易所 → 公司正式披露 → 公司官网/IR → 高质量第三方 → 普通新闻 → 社交媒体。V0.1 不接新闻和社交数据流。

数据传输方式不等同于事实权威性：日线批量获取可使用数据供应商，官方统计作口径核验；公司业务判断回到正式披露。每条记录同时保存原始发布方与传输渠道，不能因为通过某 SDK 取得就丢掉底层来源。

## 3. 已核验且影响设计的事实

1. Tushare 日线文档区分原始行情与复权，停牌期间不提供日线记录；成交量和成交额使用供应商定义单位。因此必须做单位转换、停牌识别和完整性检查，不能照搬字段名。参见[日线接口](https://tushare.pro/document/1?doc_id=27)。
2. 每日指标有账号权限要求，并区分普通流通与自由流通换手率、不同 PE 与股息率定义；本提案不锁定积分价格或承诺账号可用。参见[每日指标接口](https://tushare.pro/document/2?doc_id=32)。
3. 复权锚点与供应商计算方法会影响输出，必须保存方法和版本，不跨源混算。参见[Tushare 复权说明](https://tushare.pro/document/2?doc_id=146)。
4. 官方发布文章与统计数据库更新时间可以不同，所以不能把数据库更新时刻或统计期末当成首次公开时刻。国家统计局的日程说明给出不同更新安排，支持将“发布资料采集”和“结构化库同步”分开。参见[2026 发布日程说明](https://www.stats.gov.cn/xw/tjxw/tzgg/202512/t20251224_1962137.html)。
5. FRED 默认的 real-time period 与历史 vintage 不是同一概念；要恢复历史可知数据需显式选择时间范围。ALFRED 的日期精度也不能直接证明盘中何时可知。参见[FRED 时间语义](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)、[ALFRED 帮助](https://alfred.stlouisfed.org/help)。
6. AKShare 提供数据接口封装，其存在不证明所有底层接口稳定、允许批量使用或含原始历史版本。采用前逐接口检查来源及条款。参见[AKShare 官方文档](https://akshare.akfamily.xyz/)。

## 4. Fallback 的实际执行规则

每个数据集维护 `source_policy_version`，将权威性、字段语义、覆盖、历史版本能力、延迟、费用/权限分别记录，不用单一总分自动决定来源。

1. 首选源失败先有限重试；旧完整快照仍可用但标注 stale。
2. 备选源只有通过字段单位、证券映射、交易口径、复权方法、历史期间对照后才能发布。无合格备选则保持缺口，不从页面随意抓一个数补上。
3. 切源使用新批次、新 source_id、新 policy_version，保留原始版本。整日/字段组按一致口径切换，不从多个来源拼一个看似一致的 OHLC 或复权序列。
4. 差异超出预先验证的容差进入隔离；股价精度、金额舍入等容差分字段定义。更权威来源也不能覆盖掉不同交易范围的值。
5. 文档镜像只有内容哈希或可靠官方标识能确认同份时才合并；否则分别留存，标注可能重复。更正公告关联原公告而不是覆盖删除。
6. 模型永远不是 fallback 数据源；人工导入必须附来源、时间和单位，未验证文件标为 user_supplied，不自动晋升官方。

## 5. 前置验证清单与阻塞等级

P0 表示阻塞 V0.1 对应核心能力发布；P1 表示可明确降级；P2 表示后续版本研究。

| ID | 风险/未知 | 最小验证实验 | 通过标准 | 失败处理 |
|---|---|---|---|---|
| R01 P0 | 供应商账号权限、沪深京/退市/历史字段覆盖 | 检查现有权限；选 30 个交易日含三所/停牌/退市/除权样本，对主数据与日线分页 | 必需字段/市场有可用来源，缺口可解释，完整历史回填路径成立 | 输出缺失能力与可选源/成本；不得直接采购或假定收费权限 |
| R02 P0 | 全市场成交口径不一致 | 将合计与同口径官方统计对照，逐项解释盘后、大宗、品种范围 | 差异在约定字段精度内或有明确范围解释 | 不发布“全市场完整总额”，先修口径 |
| R03 P0 | 未来信息污染 | 初版/修订、盘后公告、迟到采集、未来分红各一组夹具 | 新加入未来数据，旧 as_of 输出不变；最新模式能变化 | 时间层未通过前不开放历史结论 |
| R04 P1 | 行业历史成员不可得 | 查一套分类的授权、变更记录与旧日成员 | 能证明指定日期成员与公布时刻 | V0.1 仅当前行业与首次采集后快照；历史功能禁用 |
| R05 P0 | 公告抓取分页/反爬/历史范围 | 三市场样本、跨多页、同日多公告、修订与重复镜像 | 可续传、无静默漏页、全部保存来源时间 | 官方允许的替代入口/文件导入；若全市场索引无自动路径，须调整范围 |
| R06 P1 | PDF 版式、扫描和表格 | 2 家公司至少 10 份多类型资料，含扫描件/跨页表 | 文本原件定位无错位；低质量与失败被识别 | 原件保留+人工阅读；OCR/表格自动化延期 |
| R07 P0 | 中文检索找不到关键业务词 | 至少 30 个短词/缩写/主营问题，人工标注正确片段 | 有文本资料集 Recall@10 ≥ 90%；无结果可解释 | 调整分词/字段检索，不能靠模型补知识 |
| R08 P0 | Tauri/Python 目标平台打包 | 本地 sidecar 含 DuckDB/Polars/解析依赖的最小运行实验 | 干净启动、健康检查、退出无孤儿、重启恢复 | 调整打包；可用 Web 继续开发，桌面版仍不算验收 |
| R09 P0 | 跨文件/DB 发布与磁盘满 | 在文件写入、重命名、manifest 提交前后强杀 | 无半批次可见，恢复后无重复/悬空引用 | 发布协议返工后再接大规模回填 |
| R10 P0 | AI 有引用但不支持结论 | 30 个金标问题含概念误导、错年收入、冲突资料、提示注入 | 关键事实引用完整率 100%；人工检查无关键无依据事实 | 缩小回答能力，只返回证据片段；不能宣告 AI 闭环通过 |
| R11 P1 | 150 GB 估算偏差 | 日线/指标 30 日与样例项目实测，模拟合并峰值 | 能列出 1/3 年增长预算及暂停策略 | 减少非重点 L3/可重建缓存，保护结构化历史 |
| R12 P2 | 历史估值/宏观 vintage 不足 | 对照若干修订期、财报重述和股本变化 | 明确 PIT 可用区间、source 与 vintage | 只做 latest_revised 或未知，不用于历史验证 |
| R13 P1 | 来源访问和模型费用失控 | 查询来源使用条件、速率、费用；试单日调用与下载预算 | 使用条件和限额记录在配置，作业可暂停 | 不启用不明确的来源，按已授权范围运行 |
| R14 P0 | 本地备份“成功”但无法恢复 | 固定研究报告，恢复到空目录后断网打开 | 快照、原件、citation、计算输入哈希一致 | 发布前修复备份边界 |

这些实验在用户确认设计后执行。本次没有调用付费数据接口、创建定时自动化或开始历史回填。

## 6. 设计决策记录摘要

| 决策 | 当前推荐 | 重新评估触发点 |
|---|---|---|
| D01 | 模块化单体、单写入所有者 | 出现真实多用户/多机协作需求 |
| D02 | SQLite 控制面、Parquet 事实、DuckDB 分析 | 实测无法达到查询/容量目标，而不是因“看起来不够先进” |
| D03 | 关键词证据检索先行 | 中文检索优化后仍有明确语义召回缺口 |
| D04 | V0.1 不合成入场/离场评分 | 完成历史样本、偏差和稳健性验证，仍保持非决策定位 |
| D05 | 全球序列与完整宏观结构化延后 V0.2 | 核心闭环完成且来源可得 |
| D06 | 日线与资料并重，先保障版本和证据 | 不因追加页面需求跳过基础验收 |
