# TheWolf 编码规范

2026-10-23有效版，适用于本轮新增或修改代码；不据此全库重构。旧语言或宿主实现只在相关任务获准时修改。业务定义见[业务约束](Business-Constraints.md)，授权见[AGENTS](../AGENTS.md)，检查深度见[独审规范](Independent-Code-Review-Policy.md)，命令见[README](../README.md#验证入口)。旧原文（仅在本地保全历史中）保留追溯。

## 1. 可读性与职责

- 名称表达业务含义，允许行业通用缩写；不按名字黑名单判断。避免难懂的链式调用、嵌套三元表达式或把不同职责塞进同一函数。
- 函数围绕清晰职责组织，上层编排多个步骤是合理的。约50—80行、三层嵌套只是考虑拆分的提示，不是硬限制；不拆出大量无意义小函数。
- 稳定重复的逻辑再考虑复用，已有清晰边界可以直接采用。抽象须解决职责、依赖或测试问题，不凭类名或层数判断设计质量。
- 沿用项目命名、目录、组件及工具配置，不夹带无关改名、重构、框架替换和依赖升级。删除前查明调用者、兼容性及暂未使用原因，不因未来规划保留无必要实现。

## 2. 注释与函数说明

说明文字使用中文，标识符、专有名词、链接及工具标签保留原样。解释代码不能直接表达的业务依据、约束和选择原因，不逐行复述。

对外接口、跨模块复用、核心业务、金融计算、清洗与来源适配、时间版本、持久化及恢复函数须写文档注释。语义明确的简单内部辅助函数、直接转发回调可省略；短函数若属于前述范围仍应说明契约。

Python用Google风格docstring，TypeScript用JSDoc，既有Rust用`///`；先一句话说职责，再按需解释参数含义、单位/时间、返回、异常、副作用及限制。不重复类型，不填空栏目。缺失值、旧版保留和失败后状态引用统一定义，行为改变时同步更新说明。

`TODO`记临时方案及处理条件，`FIXME`记已知未修问题；影响当前交付的关联status问题，不把未来想法写成开发承诺。

## 3. 类型与接口

- Python新增核心业务代码使用适用的类型标注，稳定复杂结构定义明确模型，不长期用无约束字典传递核心事实。
- 外部输入、输出、错误及可信边界执行必要运行时校验；TypeScript类型、`as`或模拟数据不能代替校验，不能用宽泛类型掩盖不一致。
- HTTP结构以现有契约为源，生成物不手改。契约、生成配置、工具版本和输出对应；按已有生成或受限适配机制核对一致性，不由实现倒灌覆盖已审定契约。
- 变更接口核对真实调用者、媒体类型、必要头、错误、字段及兼容性；新增字段或枚举不自动视为兼容。结构验证与金融语义检查分别保留。
- 有副作用请求关联已核对实例、固定配置、请求和任务，服务端在业务副作用前比较；前端、代理、宿主不透明重试写请求或换实例重发。结果归属无法证明就标未知，不用另一实例或旧结果替代；正常重连不要求逐次人工确认。

## 4. 异常、日志与配置

- 不用裸`except:`；捕获能够处理的明确异常。边界确需宽泛捕获时保留诊断、明确失败，不静默返回成功或零值。重试有边界，取消和资源清理不被吞掉。
- 核心流程用统一日志，正常CLI结果及测试输出可直接输出。记录定位问题所需的来源、任务、时间和阶段；异常文本、URL及载荷也不得泄露凭据。
- 凭据和机器专属路径不硬编码、真实私密配置不纳管。服务地址、端口、数据根集中管理，开发默认值须明确；运行时解析绝对路径是合理的。
- 独立服务及测试显式指定数据根、端口和写开关，缺必要配置失败，不自动选择真实根或创建样本。测试根核对规范化路径与符号链接，防止重叠。
- 端点、代理和实例预期来自受控配置，运行期间冻结，不接受不可信页面参数修改。公开标识不是认证，不恢复已取消的连接Token；具体契约见[正式ADR](Architecture-V0.1.md)。

## 5. 数据与模块边界

遵守[业务约束](Business-Constraints.md)中的金融单位、精度、缺值、时间版本、原件保留和发布恢复规则；算法依赖的来源与口径未知时明确限制，不能猜测或让模型补事实。

业务页面通过公共Client请求，不从其他业务页面导入网络实现。Client不管理服务进程，宿主能力由适配层提供；HTTP层调用应用服务，不直接编排采集或访问业务表。应用服务通过公开模块接口组织用例，领域层保持独立。仅实现已授权范围，不提前建设全部模块。

## 6. 测试与回归

金融计算、单位转换、日期、清洗、去重、存储、API和解析按影响安排测试，用明确输入与独立预期验证正常、边界、失败和恢复，不追求测试数量或镜像实现。

可自动复现的行为缺陷，尽量先证明修复前失败、修复后通过；视觉或低风险非自动化问题记录实际复现和检查方式。不得编造接口、删除有效失败测试、放宽正确断言或修改正确业务规则使结果变绿。公共修改验证实际调用者，界面修改检查真实界面；隔离数据和恢复遵循AGENTS。

## 7. 依赖、工具与交付

增加依赖前查标准库和已有依赖是否足够，考虑维护成本；不为几行功能引入大型依赖，不顺带升级。遵守已有格式化、静态检查、类型和构建配置，未配置或未运行不能声称通过；不借规范采用扩建工具链。

只运行受影响且必要的检查。交付按[流程模板](Task-Workflow.md#3-一页交接模板)说明改动、实际命令及结果、未验证项、影响和已知问题；小任务用简短汇报，无需另建报告。纯风格建议不强制返工，业务、安全和数据约束仍须满足。
