# 设计稿规则

本目录（`design/`）是纯 HTML 设计稿，用假数据，作用是先把页面和需求定下来，再据此开发正式前后端。规则只有下面十条，请严格遵守，不要自行增加流程。纯原型制作的独审豁免见[项目协作规则](../AGENTS.md#任务分级)。

## 先分清两类改动

- **纯视觉微调**（颜色、间距、字号、不改变含义的文案措辞）：在已授权范围内可以直接改，不需要记录，不影响模块状态。
- **改了内容**（增删页面或模块、显示内容、数据结构、统计口径、公式、更新方式，或影响数据选择与计算结果的交互发生变化）：必须同步更新受影响模块的数据说明，并在 `CHANGELOG.md` 里留痕。改变业务含义的文案属于内容变更。

## 规则

1. **范围**：设计稿只放在 `design/` 下，不写后端代码，不读取真实数据。正式开发在对应的应用代码中进行，本目录始终保留假数据。
2. **共用文件**：原始示例数据统一来自 `shared/mock-data.js`，衍生指标按数据说明中的公式计算，页面不得自行生成原始数据。样式统一维护在 `shared/shared.css`，颜色、间距、字号使用其中的变量，页面不得写死颜色；导航统一维护在 `shared/nav.js`。
3. **模块编号**：每个模块有固定编号（例如 `market-overview.02`），写在 `data-module` 属性上。编号不改、不复用，模块删除后编号作废。
4. **数据说明同步**：改了某个模块的内容，必须同步更新它的数据说明（数据、公式、更新方式）。数据说明是将来正式开发的需求，不能丢，也不能过期。共用文件的变更影响多个模块时，必须同步处理所有受影响模块的数据说明和状态。
5. **留痕**：新增或删除页面、模块，或发生内容变更、修改数据说明时，在 `CHANGELOG.md` 里新增一行（格式见下）。状态变更按下文记录。纯视觉微调不用记。
6. **状态标记**：每个模块在 `data-status` 属性上标注状态：`草稿`、`定稿`、`已开发`。状态只按模块标注，页面不单独标。状态怎么变，见下面的“定稿与正式开发”。
7. **主题与颜色**：浅色、深色两套主题都要正常。红色和绿色只用于表示涨跌（A 股：红涨绿跌），不得用作品牌色或装饰色。
8. **可打开**：断网时双击 `index.html` 能直接打开。不引入构建工具，不依赖 CDN。
9. **汇报**：改完用一两句通俗的中文说明改了什么，不要贴大段代码。
10. **不扩大范围**：没让做的页面和功能不要做，有想法写在汇报的“建议”里。

## 定稿与正式开发

状态按**模块**标，因为正式功能按模块开发。定稿表示可以作为开发依据；实际开发范围和开始时间仍需本人明确授权。

| 状态 | 含义 | 谁来改 |
|---|---|---|
| 草稿 | 还在改，不能据此开发正式功能 | 默认状态；发生下述内容变更时由修改的 Agent 同步退回 |
| 定稿 | 页面表现和数据说明已确认，可以作为正式开发依据 | **只有本人明确说“定稿”才能改**，Agent 不得自行标记 |
| 已开发 | 对应正式功能已完成前后端开发及真实数据接入，并经本人明确验收；本目录原型仍使用假数据 | 本人明确验收后，由开发的 Agent 据实标记并记录 |

状态变化的规则：

1. 草稿 → 定稿：本人明确确认定稿后，在 `CHANGELOG.md` 里加一行“定稿”，记录日期，并注明可回查的文件版本。开发依据是该次确认的页面、数据说明和数据结构；一行日志或日期本身不能代替文件版本。可以引用已有 Git 提交号或已保存版本，须覆盖相关共用文件；没有可回查版本时如实说明，不虚构版本，也不因此自动取得 Git 写操作授权。
2. 定稿或已开发的模块发生上述内容变更时，状态自动退回“草稿”，由修改的 Agent 同步标记并记录变更。“是否影响后端”按下方标准判断，不由退回草稿自动决定。本人重新确认定稿后，才能作为后续正式开发的依据；已开发模块是否需要修改后端，依据具体变更确定。
3. 只改外观或不改变含义的措辞，不影响状态。标记“已开发”时也在 `CHANGELOG.md` 中记录，依据本人对对应正式功能的明确验收。

正式开发时：

- 只依据已定稿的模块版本开发，依据包括：该模块在页面上的表现、它的数据说明、`mock-data.js` 中约定的业务数据结构。具体实施仍限于本人授权范围。
- 发现数据说明写得不清楚、无法实现或互相矛盾时，**暂停依赖该问题的开发并向本人报告**，不要自己猜，也不要自己改设计稿。
- 后端接口中的业务数据字段、类型、单位和含义，应与定稿时约定的数据结构一致。正式前端通过数据接入层切换来源，尽量复用原型的展示逻辑；`mock-data.js` 中的随机生成逻辑和展示配置不属于后端接口。
- 开发完成后，说明哪些数据已接入真实来源、哪些仍是假数据；尚未完成必要的真实数据接入或本人验收的模块，不得标为“已开发”。

## CHANGELOG 格式

在 `CHANGELOG.md`（首次新增原型时建立；既往原型在本地保全） 里，最新的放最上面，一行一条。以下仅为格式示例，不代表实际发生的变更或定稿：

```text
日期 | 页面 | 模块编号 | 改了什么 | 是否影响后端
2026-10-27 | 行情总览 | market-overview.02 | 定稿（版本：填写可回查的文件版本定位） | 否
2026-10-26 | 行情总览 | market-overview.02 | K 线副图增加成交额均线 | 影响后端
```

“影响后端”的判断标准：是否改变了模块需要的数据（包括字段、来源、单位和统计口径）、数据结构、公式、更新方式，或新增、删除了模块。新增或删除页面按其涉及的模块及数据需求判断。其他变更填“否”；纯视觉微调不用记录。
